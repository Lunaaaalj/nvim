# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

Opinionated Neovim config written in Lua using `lazy.nvim` as the plugin manager. Targets macOS, primarily run in kitty (inline images, the PDF viewer and Molten plots use the kitty graphics protocol; Alacritty still works without them).

## Architecture

### Load order

`init.lua` → `lua/defaults/init.lua` → options, keymaps, lazy bootstrap, colorscheme restore → all plugin specs under `lua/plugins/`

### Key separation

- `lua/defaults/` — core Neovim settings (not plugin-specific): options, keymaps, lazy bootstrapping, and LSP server setup (`lsp.lua`)
- `lua/plugins/` — one file per plugin (or tightly related group), each returning a lazy.nvim spec table

### Colorscheme

The last used colorscheme is persisted to `stdpath("state")/colorscheme` (machine-local, **not** in the repo — `.colorscheme` is gitignored and only read once as a legacy migration) and restored on startup via `lua/defaults/init.lua`. Any `:colorscheme` call triggers an autocmd that writes the name to that file. The startup load is wrapped in `pcall` and falls back to `kanso`, so a missing/uninstalled scheme never aborts startup. `<leader>cs` opens Telescope with live colorscheme preview.

Installed schemes (one file each under `lua/plugins/`): catppuccin, kanagawa, kanso, lackluster, nightfox, everforest, melange, gruvbox-material, zenbones (+ its variants forestbones/neobones/kanagawabones/seoulbones). Warm set: rose-pine (`name = "rose-pine"`), kanagawa-paper, bamboo, flexoki (`name = "flexoki"`; no transparency option, relies on the strip autocmd), evergarden, vesper (dark only). **evergarden sets `'background'` from its variant**, so its spec chooses the variant (`fall`/`summer`) from `vim.o.background`; bamboo's colors file resets its modules on every load, but its options live in `vim.g.bamboo_config` so they survive. The palette leans earthy (grays/greens/browns), minimalist, with dark and light variants.

**Transparency:** by default every colorscheme renders with no editor background so the Alacritty background shows through. This is enforced two ways, both gated on `vim.g.ui_transparent`: native `transparent` options are set per-plugin where supported (each theme spec passes `vim.g.ui_transparent`, never a literal `true` — keep that when adding a theme), and a global `ColorScheme` autocmd in `lua/defaults/init.lua` (`transparent_groups`) strips the bg of core groups after any scheme loads — covering schemes without a transparency option (e.g. melange) — and returns early in solid mode. Add new groups to that list if a plugin leaves a background.

**Toggles (`lua/defaults/ui_toggle.lua`):** `<leader>ub` / `:ToggleTransparency` flips transparent ↔ solid, `<leader>uB` / `:ToggleBackground` flips `'background'` dark ↔ light, `<leader>uT` / `:ToggleAutoTheme` makes `'background'` follow the macOS appearance. **Preferred schemes (VS Code–style):** a `ColorScheme` autocmd (registered in `restore()`, before the strip autocmd) files every loaded scheme that really draws the current `'background'` under `schemes.dark|light` in `ui.json` (so `<leader>cs` in each mode chooses them); `set_background(target)` loads `schemes[target]`, else keeps the current scheme and flips its variant, and records the result. `switching` mutes the recorder while that function loads schemes, so a failed attempt (vesper under light) is never filed; the autocmd's `scheme_is_light()` check does the same for user loads. In auto mode `startup_scheme()` feeds `defaults/init.lua`'s startup load so the right scheme comes up without a swap. State (including the `auto` flag) persists to `stdpath("state")/ui.json` and `restore()` runs **before** `require("defaults.lazy")` because the theme specs read the flag in `setup()`. A toggle finds the active theme's lazy plugin by locating `colors/<name>.{lua,vim}` on the runtimepath (no hand-kept name→plugin table), re-runs its `init`/`config` (nightfox/catppuccin hash options and recompile on change), and reloads the scheme. Transparency is independent of dark/light (kitty swaps its own background with the macOS appearance via its `*-theme.auto.conf`, so a transparent light scheme is readable); `set_background(target)` is the shared path (no-op without a reload when it already draws the target) and clears `g:colors_name` before setting `'background'` (otherwise Neovim auto-reloads the scheme with its _old_ config, which variant-driven schemes like evergarden flip straight back), and a scheme with no variant for the target — pins `'background'` back (nightfox, lackluster) or ignores it and keeps drawing dark (vesper; detected by `Normal` bg/fg luminance) — is undone completely, `'background'` included, with a warning. **Auto mode:** `restore()` reads `defaults read -g AppleInterfaceStyle` synchronously (before the themes load; `Dark`, or exit 1 = light) and a `VimEnter` check warns if the startup scheme can't draw it; afterwards a 5 s `vim.system` poll (stopped on `FocusLost`) plus `FocusGained` re-check off the main loop, and auto acts only when the system value *changes* (one warning per change for variant-less schemes). A manual `<leader>uB` turns auto off. Inside Alacritty (`$ALACRITTY_SOCKET`), solid mode sets `window.opacity=1` live via `alacritty msg config`, and transparent mode / `VimLeavePre` run `--reset` to restore `alacritty.toml`'s value.

**UI chrome (`lua/defaults/options.lua`):** a few options keep the UI clean against the transparent background. `fillchars` blanks the end-of-buffer `~` and uses a thin `│` window separator. The `cursorline` is owned by `lua/defaults/cursorline.lua` (required from `defaults/init.lua` _after_ the strip autocmd so its `ColorScheme` handler runs second): it is on only in the focused regular-file window and explicitly **off** in terminals, floats (Zen), and `skip_ft` filetypes, because window-local options are copied into new windows; neo-tree is `unmanaged_ft` (its cursorline is the selection marker); `w:no_cursorline` opts a window out. In transparent mode the default style is number-only (accent bold `CursorLineNr` from the scheme's `Function` fg, `cursorlineopt=number`); `<leader>uc` cycles number → underline (single-colour `sp`) → band (blended tint). Highlights use `nvim_set_hl` (replace, not merge). Solid mode leaves the scheme's own cursorline band alone. Accent/blend helpers live in `lua/defaults/colors.lua` — reuse them for any theme-derived accent instead of hardcoding colours. **Neo-tree (`lua/plugins/neo-tree.lua`):** every tree colour comes from one `highlights()` function (re-run on `ColorScheme`, built from `defaults/colors.lua`): hierarchy by weight (directories bold, files plain, the editor-open file in the accent, guides/dotfiles/ignored faint), git names in the scheme's gitsigns colours. Because `cursorline.lua` blanks `CursorLine` in transparent mode and leaves neo-tree in `unmanaged_ft`, the tree tints its own `NeoTreeCursorLine` and pins `cursorlineopt=line` in a `neo_tree_buffer_enter` handler. The Files tab overrides the `file`/`directory` renderers: files carry git state as name colour only, a folder shows one `•`; the Git and Buffers tabs keep the letters. Glyphs in that file are BMP `\u{}` escapes (literal ones were once stripped to empty strings, and neo-tree's default `folder_empty*` icons are nf-md tofu). `Y` (path menu), `gO` (Finder), `F`/`g/` (Telescope scoped to the node's directory) are filesystem commands. `pumblend`/`winblend` give the popup menu and floats slight transparency. Diagnostics use icon signs (via `vim.diagnostic.config`) instead of the default `E`/`W`/`I`/`H` letters.

### Aesthetics & ambience

A layer of plugins exists purely for a pleasant feel (one file each under `lua/plugins/`):

- **`snacks.lua`** — enables the snacks `dashboard` module (and has the `scroll` module configured but **disabled** for now: `scroll.enabled = false`) (snacks itself comes in via `claudecode.nvim`). The dashboard is a **minimal single column**, everything centered, and **transparent** — its `SnacksDashboardNormal` group is in the `transparent_groups` list in `lua/defaults/init.lua`. Sections: header art (read verbatim from `dashboard-header.txt` in the config root if it exists, else a built-in Python snake; `dashboard.width` = the art's widest line, floor 60), a **big block-digit clock** (`lua/defaults/bigclock.lua`: 5-row font, one pixel = 2 cells so digits stay upright; the blank margin every row shares is trimmed, because snacks centres rows by string width and the glyphs' empty pixel columns put the digits off-centre against the date) + date, a **GitHub stats line** (open PRs · issues · contributions · streak), and a **one-line key hint**; the stats line and the hint sit together as a two-line footer under the clock (no extra gap), so the block stays compact and the art keeps clear of one box. The `keys` table drives both the hint (entries with `hint`) and the bindings (every entry as a `hidden = true` item), so g/n/p/l/m stay bound without rows; `d` and `R` (git repos only: `.git` dir or file, not descended into, dotdirs pruned except `.config`) share one `pick_cd()` that streams `find` through the `proc` finder — add keys there, not as separate sections. The clock is a uv timer aligned to the minute that only runs while a `snacks_dashboard` window is visible (started on `SnacksDashboardOpened`/`BufEnter`, stopped on leave). Colors are `DashboardMuted` (Comment fg) plus `DashboardAccent`, which is the scheme's **foreground** (`Normal` fg, bold — not the `Function`-fg accent), re-applied on `ColorScheme` — no hardcoded palette.
- **`lua/header_art/`** — animated generative background over the **whole dashboard window** (a plain module, `require("header_art").setup(opts)` from the snacks spec, which holds `header_art_opts`: `enabled`, `piece` plasma/torus/orb/rings/flow/terrain/galaxy/galaxies/descent, `charset` classic/blocks/dots/binary, `fps` 30, `speed` 0.4, `brightness`, `halo`, `steps`, `animate`). `pieces.lua` has one `fn(w, h) -> frame(t, val)` per piece, working in a normalised 65×44 space so each keeps its look at any window size (the cell is ~2:1, so geometric pieces — torus, orb — scale by `min(w/65, h/22)`). `galaxy` (one Sc spiral around the content) and `galaxies` (four small ones in the free corners) are **particle** pieces (`particle_piece`): stars scattered around log-spiral arms + disk + bulge, turned rigidly (toward −θ so the arms trail) and splatted bilinearly, tone-mapped `1 − exp(−acc·gain)` with `gain` fixed on the first frame from the 98.5th percentile. They were chosen from a browser mockup (artifact `Galaxias Sc`); the same LCG and `rand()` call order reproduce its stars exactly, and `GALAXY_TIME = 2.5` makes the default speed 0.4 match the mockup's speed 1. A per-cell field formula looked like blotches, not a galaxy. `descent` is the portfolio's loss surface (`~/Downloads/GitHub/portfolio/src/scripts/surface.ts`, same Park–Miller generator), chosen as proposal C of the `Superficie de pérdida` mockup: one-cell level-set hairlines (a level between a cell and its right/lower neighbour, as in marching squares; ≥2 levels between neighbours = crowded, dropped), graphite gradient probes every 0.5 s, and two ripples from each probe that settled. Its `Δ` scales with the wells (`0.15 · 18.4 / s0`) so a small window (the picker preview) isn't matted with lines. `spiral` is sketch B of the `Log Spiral Sketches` mockup: four `r = a·e^(bθ)` arms (pitch 0.26), phase `n(θ − ln ρ / b) − ωt` (rotating a log spiral equals scaling it, so one term gives both), a slow wave outward along the arms and a dimming toward the edge. Geometry is isotropic (a row = 2 cell widths) with ρ scaled so the window corner is 1.41 (the mockup's 56×28 grid), and `SPIRAL.time = 0.7/0.4` makes the default speed 0.4 match the mockup's 0.7. **The second set** (`hilbert`, `rain`, `aurora`, `turing`, `attention`, `kmeans`, `matrix`, `warp`, `life`) comes from the `Art Sketches` mockup (56×28 grid, speed 0.4 = the dashboard default, so no time scaling) with the chosen knobs baked in: Hilbert order 4, rain 0.5 drops/s, 3 curtains, Turing mitosis (F 0.0367, k 0.0649), attention sharpness 1, 3 clusters, matrix density 0.5, warp streak 0.035, life density 0.16. Each is built for the window size: the Hilbert step is `sc` columns by `sc/2` rows so the square stays square; rain rings and the k-means blobs scale with `min(w, 2h)/56`; the aurora's sway scales with width and its heights with height; attention is a centred square grid of 14×14 blocks; warp's projection scales with the corner distance. **Stateful pieces** (`turing`, `kmeans`, `life`) step by the time between calls through `clock()` (0 on the first call or when `t` goes back, capped at 0.25 so a stalled frame doesn't fast-forward), because the picker preview drives its own `t`; a resize rebuilds them. Turing runs 400 warm-up steps at build (about 20 ms at 200×50), and its kernel is anisotropic (x 0.25, y 0.0625) so spots are round in a 2:1 cell. Glyph pieces (`hilbert` box drawing, `kmeans` borders and `o`/`@`, `matrix`) write `chr` and are ASCII or box-drawing only, so each is one cell wide in any font. **Frame contract:** `frame(t, val, chr)` — `chr` is cleared to `false` by the renderer each frame and a piece may put a character in a cell (a contour's direction); `cell()` then uses it instead of the charset, and only the level picks the colour. Pieces that ignore `chr` are unaffected. `init.lua` never edits buffer text: snacks owns the lines (`D:render` builds `self.lines` for the content plus top padding and re-sets them on `Update`), so the art is **overlay extmarks in its own namespace** (`virt_text_pos="overlay"` + `virt_text_win_col`, one per run of free cells; snacks only clears *its* namespace) and `virt_lines` on the last line for the rows below the buffer. The art keeps clear of **one rectangle** around all the text (`content_box`: padded `PAD_R`/`PAD_C` with `halo`, rebuilt only when `changedtick`/width change), fading in over `FADE` cells outside it (smoothstep, rows count double) — a per-cell halo left ragged notches around each section. `virt_lines` can't skip cells, so they get blanks inside the box. Levels are quantized to `steps` highlight groups `HeaderArt1..N` (dim tone → `Normal` fg, dim derived from `Comment` over `terminal_bg` in transparent mode, `Normal` bg otherwise; re-made on `ColorScheme`). The uv timer runs only while a `snacks_dashboard` window is visible and Neovim is focused (`FocusLost` stops it); `animate=false` draws one frame and repaints on `SnacksDashboardUpdatePost`/resize. Animation time accumulates `dt * speed` (dt capped at 0.25 s), so changing speed never jumps the phase. When `enabled=false` the braille `dashboard-header.txt` section (now a function in the snacks spec, re-run on each render) shows again. `<leader>uA` / `:HeaderArt [pick]` opens `header_art/picker.lua`, a Telescope picker modelled on `<leader>cs`: its previewer animates the piece itself via `render_frame()` (works away from the dashboard), each selection also `apply()`s it to a visible dashboard, `<CR>` persists, `<Esc>` (via `actions.close:enhance`) restores the original. The piece and on/off persist to `stdpath("state")/header_art.json` (picker, toggle `<leader>ua`, `:HeaderArt next`) and `load()` in `setup()` lets them win over `header_art_opts`; other `:HeaderArt …` options are session-only. Don't set `layout_config.preview_width` on a picker: the global Telescope layout is `flex`, which rejects it.
- **`lua/defaults/dashboard_data.lua`** — the async/cached data layer behind the stats line. **One** `gh api graphql` request (authenticated `viewer`, no hardcoded username) returns the contribution calendar plus `search { issueCount }` for open PRs and issues — exact counts, unlike `gh search … -q length`, which is capped at gh's default limit of 30. The streak is computed from the calendar's `date`s against the local date (today may be empty; days after today are ignored). The result is written to `stdpath('cache')/dashboard/stats.json` with a 30-min TTL; the section reads the cache instantly (never blocking startup) and a debounced `Snacks.dashboard.update()` refreshes when the fetch returns. `setup({ issues = "assignee" | "author" })` picks which issues count (default: assigned; the cache is keyed on it). No `gh`/not authed → no cache → the line is hidden.
- **Fades vs. transparency:** a terminal cell is either a solid colour or the terminal bg, so anything that fades over a transparent editor needs to be told what colour is behind it. That colour is `require("defaults.colors").terminal_bg` (Alacritty's default `#181818`; `alacritty.toml` sets none) — used by **`smear_cursor.lua`** (`transparent_bg_fallback_color`; also stiffer than default) and **`tiny-glimmer.lua`** (flash on yank, `transparency_color`; only yank is on, so `p`/`n`/`u` aren't hijacked). Prefer motion over opacity for new animations: nvim-notify uses `slide`, not `fade`. snacks.scroll is 140ms outQuad (50ms for held-key repeats); mini.indentscope's guide grows out over 80ms.
- **`colorizer.lua`**, **`rainbow-delimiters.lua`**, **`tiny-devicons.lua`**, **`satellite.lua`** (scrollbar with git/diagnostic/search marks), **`illuminate.lua`** (word-under-cursor), **`precognition.lua`** (motion hints), **`cellular-automaton.lua`** (fun screensaver), **`typr.lua`** (typing practice + stats, via `nvzone/volt`).

When adding cursor/scroll-animating plugins, check this list first — multiple plugins animating the same thing will conflict.

### LSP

Two-layer setup:

- `lua/plugins/mason.lua` ensures the servers are installed via mason-lspconfig (`clangd`, `pyright`, `ruff`, `ts_ls`, `html`, `cssls`, `emmet_language_server`, `texlab`, `tinymist`, `lua_ls`) and configures them through Neovim 0.11's native API: shared cmp capabilities go on `vim.lsp.config("*")`, per-server overrides (capabilities/settings/filetypes/on_attach) live in the `servers` table and are applied with `vim.lsp.config(name, opts)`, and mason-lspconfig v2's `automatic_enable` calls `vim.lsp.enable` for each installed server (v2 has no `handlers` option — don't reintroduce one, and register configs _before_ `mason-lspconfig.setup()`) — `clangd` pins utf-16 offset encoding, `pyright` defers import-organizing to `ruff`, `ruff` drops its hover so it doesn't duplicate pyright, `tinymist` formats with typstyle and exports `foo.pdf` on save, `pyright` gets the project interpreter from `lua/pyenv.lua`. The same file also registers **mason-tool-installer** to guarantee the non-LSP tools conform/dap call by name (`ruff` — conform's `ruff_organize_imports` + `ruff_format` for Python; R uses the `styler` package —, `stylua`, `clang-format`, `latexindent`, `typstyle`, `prettier`, `codelldb`, `debugpy`).
- `lua/defaults/lsp.lua` is a single global `LspAttach` autocmd that binds buffer-local keymaps (`gd`/`gD`/`gr`/`gi`/`gy`/`<leader>rn`/`<leader>ca`/`[d`/`]d`) for **any** attached server, and enables inlay hints (toggle `<leader>uh`) when the server supports them. The same file wraps `vim.lsp.handlers["textDocument/inlayHint"]` to flatten whitespace in hint labels and cap them at 40 cells: texlab's `\ref` hints copy multi-line `\caption`s, and a raw `\n` in inline virtual text desyncs the terminal from Neovim's grid, smearing text over neighbouring windows (the kitty PDF preview) on scroll. It is `require`d from `lua/defaults/init.lua`. Do not add per-server `on_attach` keymaps — extend this autocmd instead. `K` is deliberately **not** bound there: its single owner is `lua/plugins/ufo.lua` (peek fold → hover.nvim, which includes the LSP provider), and a buffer-local map would shadow it.

`lua/plugins/lsp.lua` just pulls in `nvim-lspconfig`. Add new LSP servers to `ensure_installed` (and `servers` for overrides) in `mason.lua`.

A `.luarc.json` at the config root configures lua_ls for this repo: it declares `vim` and `Snacks` as globals so editing the config produces no spurious "undefined global" warnings (LuaJIT runtime, third-party checks off). Add to its `diagnostics.globals` if another runtime global trips lua_ls.

### Spell audit and writing companion (quill.nvim)

`lua/plugins/quill.lua` loads **quill.nvim**, a standalone plugin developed in `~/Downloads/GitHub/quill.nvim` (`dir =` spec, lazy on `cmd`/`keys`; its own README and `:help quill` are the reference, `make test` runs its headless suite with `claude.run` stubbed). The Lua module is still **`writing`** (`require("writing")`, `:checkhealth writing`). It holds the spell audit (`:SpellAudit`, `<leader>sa`), the shared audit walker (with `l` later and `t` talk), and the Claude writing companion (`:Writing …`, `<leader>W`): grammar, STYLE.md paragraph restyle (`<leader>Ws`) and finding-by-finding conformance (`<leader>WS`; the nearest `STYLE.md` is the style guide; suggestions that invent numbers/citations are withheld as "needs input", counted in lualine, listed by `<leader>Wn`), rigor review, reverse outline, rewrite/ask/chat, the later list (`<leader>Wl`) and the session model picker (`<leader>Wm`), all through `claude -p` with the Claude Code login (never `--bare`). **No `require` of this config from the plugin**: the glue is in the spec. The keys are `<Plug>` maps (`<Plug>(SpellAudit)`, `<Plug>(WritingGrammar)`, …), bound in lazy `keys` through a `plug()` helper that sets **`remap = true`**, because lazy (like `vim.keymap.set`) maps a string rhs non-recursively and a noremap `<Plug>` target does nothing. The walker's "… again resumes" hint looks up whatever key is mapped to the `<Plug>`. Theme colours: the `highlights` option is a **function** (built from `defaults/colors.lua`) that the plugin re-runs on every `ColorScheme`, overriding its `default` links (`SpellAudit*`, `Writing*`). `chat = function(prompt, ctx)` opens the companion chat via `claude_chats.open({ win = ctx.win, prompt })` (the plugin makes the split; its fallback is `:terminal claude`). The spec also adds a "Translate to Spanish" rewrite preset (`assist.presets` replaces the list). The filetypes `spellaudit` (walker float) and `writingoutline` (outline/rigor panels) stay in cursorline.lua's `unmanaged_ft`. The which-key `<leader>W` group and the cheatsheet entries stay in their files. `zg`/`a` in the spell audit writes to 'spellfile', by default `~/.config/nvim/spell/<lang>.utf-8.add` (inside this repo).

### Window layout

`lua/layout/` (a plain module, `require("layout").setup()` in `lua/defaults/init.lua`) keeps the editor wide when panels open. Every panel opener (claudecode's snacks terminal, toggleterm's vertical shells, refdocs) does a `botright vsplit` with a fixed width, so each used to add a full-height column and the editor took the whole squeeze. A `WinNew` hook (it scans for windows without `w:layout_seen`, because `nvim_open_win` without `enter` leaves the old window current) runs `arrange()` on the next tick. A panel (`buftype` terminal/help, or `b:refdocs`) that is the rightmost leaf of the main row gets one of two treatments. If the window to its left is already a panel column, it is **moved** below that column's last window with `nvim_win_set_config(win, { split = "below", win = … })`. That keeps the window id, so toggleterm/snacks keep tracking it. The heights are then evened and the column gets its remembered width back (`w:layout_width`, refreshed on `WinResized`), because the opener's split already squeezed it. Otherwise it is the first panel, narrowed so the editor keeps `editor_min` (88). Bottom panels and splits made inside the column are left alone. **`rebalance()`** re-establishes the layout after anything changes it (`WinClosed` of a non-float, `VimResized`, a new non-float window e.g. neo-tree), coalesced to one scheduled pass: on the widest main row, neo-tree (leftmost leaf) and the panel column (rightmost frame, all leaves panels) are set back to `w:layout_width` — the width you want — the column clamped so editors keep `editor_min`, and editors take the slack (setting an edge window's width moves columns to its inner neighbour). It does nothing when no editor sits between them. A column whose leaf count differs from `w:layout_col_n` evens its heights. `WinResized` only records a width as yours when it differs from `w:layout_applied` (the last width set here) and no close/resize is `settling`, so Neovim's own redistribution never overwrites your widths. `WinResized` is fired from the main loop, so headless tests inside one `luafile` never see it — drive a `--listen` instance over RPC instead. `<leader>u=` = `rebalance()` + `wincmd =` (which leaves `winfixwidth` windows alone). `<leader>uw` toggles `g:layout_auto`. **`equalalways` is off** (options.lua): with it on, every split re-evened all windows, and switching it back on re-evens immediately, so don't toggle it around a split. Instead, neo-tree windows get `winfixwidth` (otherwise a panel's `vertical resize` eats neo-tree), and windows that start showing a normal file (`buftype == ""`) lose it (window options outlive the buffer). Manual splits: `<leader>|`/`<leader>-`/`<leader>\` (longer side), `M.split()` lifts the current window's `winfixwidth` so splitting a panel halves it; `<leader>fb` is Telescope buffers (`<C-v>`/`<C-x>`).

### Language references

`lua/refdocs/` (a plain module, `require("refdocs").setup()` in `lua/defaults/init.lua`) shows offline reference pages from tools that know the installed versions: C via `man` (sections 3 → 2 → 1, so `printf` is printf(3)), C++ via `cppman` (cppreference; needs `groff`, pages cached in `~/.cache/cppman`), Python via `python -m pydoc` run with the file's project venv (`.venv`/`venv`/`env` upward to `$HOME`, then `$VIRTUAL_ENV`/`$CONDA_PREFIX`, never the Neovim host venv), R via `tools::Rd2txt` on the installed help (any installed package; Rscript runs in the file's dir so renv applies, and Rscript adds `--args` itself — don't pass it). `backends.lua` has one table per language (`topic`/`cmd`/`list`/`child`); the language is the filetype, or the enclosing chunk's language in quarto/markdown/rmd. Topic resolution: Python resolves `import … as` / `from … import` aliases from the buffer; C++ qualifies `v.push_back` with the receiver type from a synchronous clangd hover (``Type: `std::vector<int>` ``). Output is plain text shown as filetype `man` (headings, `gO`). Three entry points: the `refdocs.hover` **hover.nvim provider** (priority 999, just under the LSP group's 1000, so `K` shows LSP and `<C-n>` the reference; hover.nvim is configured through its `providers` list, and the stock man provider is restricted to shells/make because it looks up section 1); `<leader>K` / `:Ref` (full page in one reused split, buffers `ref://<lang>/<topic>` kept hidden so `<C-o>` works; `K`/`<C-]>` inside a page follow the word, via `child()` relative to the page's topic); `<leader>fd` / `:RefSearch` (Telescope over every topic, cached per session; Python's list is per interpreter).

### Project settings (projectrc.nvim)

`lua/plugins/projectrc.lua` loads **projectrc.nvim**, a standalone plugin developed in `~/Downloads/GitHub/projectrc.nvim` (`dir =` spec, `lazy = false` because its appliers must see the first FileType; its own README and `:help projectrc` are the reference). It keeps VS Code–style per-project settings in `.nvim/settings.json` (flat dotted keys + `"[ft]"` overrides), edited in a float (`<leader>,` / `:ProjectRC`, tabs Editor/Format/LSP/Build/Debug), and stores settings other tools read in **their** files (`.clang-format` keys edited in place, a marked fragment in `.clangd`). Settings that run something are ignored until the file is trusted in the 'exrc' hash db. ### Git worktrees

### Buffer-centric quitting

`lua/defaults/bufclose.lua` (required from `keymaps.lua`) makes `:q` close the **buffer**, not Neovim. It is wired as a command-line `<CR>` `expr` mapping that rewrites a whole-line `q` / `q!` / `wq` / `wq!` to `:BufQuit[!]` / `:BufWriteQuit[!]` — **not** `:cabbrev`: a `q` abbreviation doesn't expand when `!` follows, and a `q!` abbreviation never matches, so `:q!` would still exit. `:quit`, `:qa`, searches and `<cmd>q<cr>` inside mappings are untouched. In a split / float / neo-tree / multi-tab, BufQuit is a plain `:quit`; in the last editing window (floats, neo-tree and panels — terminals incl. Claude's, help, previews — don't count; only file buffers/the dashboard do, otherwise closing the editor beside a panel hands its columns to neo-tree or the panel, both `winfixwidth`) it switches to the next listed buffer (files before terminals, then MRU) or opens the dashboard **in that window** (`Snacks.dashboard.open({ buf, win })` — without `win` snacks opens a float), and `:q` on that dashboard runs `:qall`. Terminal/unlisted buffers are only hidden (jobs survive); modified buffers prompt Save/Discard/Cancel. `<leader>x` calls the same `close_buffer()`.

### Terminals

`lua/terminals/` (a plain module, like `claude_chats`) owns terminal sessions; `lua/plugins/toggleterm.lua` only draws the windows and forwards toggleterm's `on_create`/`on_open`/`on_exit` to it, then calls `require("terminals").setup()`. **Ids are partitioned:** shells 1–99 (`new()` takes the first free id), the pinned REPLs 100+ (`M.repls`) — toggleterm hands out the lowest free id from one pool, so never create a terminal without an explicit id. Per-terminal state (`info(id)`: custom name, cwd, running command, last command, exit, output rows, unseen) is fed by **zsh prompt hooks**: shells get `ZDOTDIR=shell/zsh` (+ the real one in `NVIM_TERM_ZDOTDIR`), whose `.zshenv` restores the user's ZDOTDIR, sources their files unchanged, and (interactive only — toggleterm runs `zsh -c "zsh;#toggleterm#N"`, so the outer non-interactive zsh must keep pointing at the wrapper) emits OSC `633;E;<cmd>`, `133;C`, `133;D;<status>` and `7`, read through the `TermRequest` autocmd. The cursor rows at C/D are the first output row and the row after the output (1-indexed), which `quickfix()` uses (with a `%D` line in the errorformat so paths resolve against the shell's cwd). "Last used" is set only by `on_open`/`TermEnter`, **not** `BufEnter` (toggleterm moves focus through other terminal windows while closing). State changes fire a debounced `User TermsChanged`, consumed by the winbar (`winbar_label`, toggleterm's per-terminal `name_formatter`) and the neo-tree source `terminals/neotree/` (`name = "terminals"`, tab in `lua/neotree_tabs.lua`). Python paste: 3.13+ (pyrepl) gets bracketed paste and a **separately delayed** second Enter (pyrepl reads a fast burst as more paste); older REPLs get blank lines stripped. Sessions: `persistence.lua` stores `session_state()` as JSON in `g:Session_terminals` and `session_restore()` re-spawns them.

### Music

`lua/music/` (a plain module, `require("music").setup()` in `lua/defaults/init.lua`) controls the **Apple Music app**; Neovim plays no audio. `applemusic.js` (JXA, `osascript -l JavaScript applemusic.js <cmd>`) answers every command with one JSON line, and state-changing commands return the fresh poll so the UI updates at once. It checks `Application("Music").running()` **before touching any property**, because any property access launches Music. Track lists use bulk reads (`tracks.name()`: one Apple Event per field, not per track), so the whole library takes ~170 ms. `artwork.applescript` writes a track's raw art to `<id>.dat` (not `.raw`, which magick reads as camera RAW), and magick turns it into a 512px PNG at `-density 1` (see PDF viewer › Sizing) in `stdpath("cache")/music`. `init.lua` holds `M.state` and polls on an adaptive one-shot timer (1 s with the player open, 3 s playing, 5 s paused, 15 s with Music closed, plus `FocusGained`). `M.position()` interpolates between polls, so **the lualine component (`lualine_x`) only reads cached state** and never shells out. Changes fire `User MusicChanged`, which refreshes lualine. `vim.system` has an 8 s timeout, because Apple Events block for up to 2 minutes while macOS shows its Automation prompt. Error `-1743` (permission denied) stops polling. After a command that answers mid-transition (no track yet), it re-polls after 600 ms. `ui.lua` is a library browser float above a now-playing card. The browser has tabs Playlists/Artists/Albums/Songs/Queue, with one item per line so `j`/`k`/`G` work natively. Per-tab drill-down stacks, the cursor and the filter live in module state, so they survive closing the player. The selection is the float's own cursorline, so `music` is in cursorline.lua's `unmanaged_ft`. The album art is a third, borderless float (`relative = "win"`, zindex 51) over the card's left padding, because `Snacks.image.buf.attach` draws over a whole buffer. **All the floats set `winblend = 0`:** kitty locates an image by its placeholder cells' fg colour, and the global `winblend = 10` blends that colour, so the art silently doesn't draw. It uses pdfview's exported `fix_snacks_spinner()`. **Cover grids:** album and playlist views (`grid = true`) render as tiles (7 rows of art, a title and a subtitle) when `Snacks.image.supports_terminal()`; otherwise they're lists. Each cover is a snacks _inline_ placement with `conceal = true` and a `range` spanning the art rows. That is the code path where snacks overlays each image row at a fixed `virt_text_win_col`, so covers sit side by side and scroll as text. The list window therefore keeps `conceallevel = 0`. In grid mode `v.cursor` is the tile index, not a line. Caption byte ranges are recorded at build time, because titles with accents or Cyrillic make bytes ≠ cells. Scrolling snaps to whole tile rows, which needs window-local `scrolloff = 0` (the global 8 re-scrolls). The list height is a whole number of tile rows. A re-render bumps `ui.gen`, so covers arriving for an old layout are dropped. `music.artwork()` runs at most 3 exports at once; `urgent` (the now-playing card) jumps the line. A playlist's cover is its first song's art (`first` from the `playlists` command). `library.lua` dumps every track once (`library` command, ~190 ms) and groups albums (album artist + album, sorted by disc/track) and artists locally. "Play album/artist" and `a` go through a **`Neovim Queue` user playlist** (`queue_set`/`queue_add`), because Music has no play-album command and Up Next isn't scriptable. Each track is found with its own `whose({persistentID})` (~12 ms). A bulk `persistentID()` read plus `tracks[i]` copies the **wrong songs**, because the bulk order doesn't match element indexing. Create playlists with `Music.make`; `userPlaylists.push` fails with "Can't convert types". Highlights `MusicAccent`/`MusicTitle`/`MusicMuted`/`MusicSel` come from `defaults/colors.lua`. Keys live under `<leader>M`, because `<leader>m` is Molten.

### Zotero (ibid.nvim)

### LaTeX

Five layers, all of which hang off VimTeX initialising correctly:

- **`lua/plugins/vimtex.lua`** — VimTeX itself, `lazy = false` (its ftplugin must register before the first `.tex` buffer). **Pinned to `tag = "v2.18"`**: VimTeX HEAD raised its floor to Neovim 0.12.4 on 2026-07-22, and on an older Neovim the version gate `finish`es `ftplugin/tex.vim` _before_ `vimtex#init()` — killing every mapping, the latexmk compiler, and `vimtex#syntax#in_mathzone()`. Drop the pin once Neovim is 0.12.4+.
- **In-terminal preview: `lua/pdfview/tex.lua`** (`<leader>lv`, also visual; `<leader>lF` live follow). It builds on the PDF viewer (see **PDF viewer** below). Forward search runs `synctex view` once per line, and the `h/v/W/H` boxes become accent highlights. Inverse search maps the clicked page point to `synctex edit -o page:x:y:pdf`. Paths need `simplify()` because synctex reports `dir/./file`. The PDF comes from `b:vimtex.compiler.get_file('pdf')`; v2.18 has no `b:vimtex.out()`. `VimtexEventCompiling`/`CompileFailed`/`CompileSuccess` set the winbar status. Success with `config.follow` re-syncs to the cursor. Outside a graphics terminal it falls back to `:VimtexView`.
- **No Skim.** `vimtex_view_automatic = 0` and `vimtex_view_method = "general"` with `open` (system viewer, only for `<leader>lV` and the non-graphics fallback). The skim method's `compiler_callback` talks to Skim after _every_ compile even with automatic off, so don't switch back to it. Instead `pdfview.tex` opens the kitty preview on the first `VimtexEventCompileSuccess` (once per PDF per compile session, reset on `VimtexEventCompileStopped`); its hooks are registered on `VimtexEventInitPost` from the vimtex spec, so they exist before the first `<leader>ll`.
- **LSP/format** — `texlab` (mason `ensure_installed`) and `latexindent` for `tex` in conform.
- **Snippets** — `lua/snippets/tex.lua`, a Castel-style set loaded by LuaSnip's `from_lua` loader. Math-mode autosnippets gate on `vimtex#syntax#in_mathzone()`, so **they die silently whenever VimTeX fails to init** — check VimTeX first if snippets stop firing.

Treesitter highlighting is deliberately `disable`d for `latex` (`lua/plugins/treesitter.lua`) so VimTeX owns syntax + conceal; the parser stays installed for folding/textobjects/context.

Debugging tip: VimTeX starts viewers **detached**, so viewer failures are invisible inside Neovim (`<leader>lV` just does nothing). Run `<leader>li` (`:VimtexInfo`) and reproduce the printed viewer command in a shell, where stderr is visible.

### Typst

Neovim already detects `*.typ` as filetype `typst`. **tinymist** (mason) does LSP + formatting (`formatterMode = "typstyle"`, `exportPdf = "onSave"` writes `foo.pdf` beside `foo.typ`); conform also runs `typstyle`; treesitter highlighting stays **enabled** (nothing else owns Typst syntax). The preview is **not** typst-preview.nvim/a browser: it is `lua/pdfview/typst.lua`, a backend of the shared live preview (see **PDF viewer**), so `.typ` buffers get the same kitty split as LaTeX. Buffer-local maps in `lua/defaults/keymaps.lua` (`TypstKeymaps`) reuse the LaTeX keys: `<leader>lv` live preview (also visual), `<leader>lF` follow, `<leader>lk` close, `<leader>lo` compile once to `foo.pdf`, `<leader>lV` compile + open in the system viewer, `<leader>le` diagnostics loclist. **Templates:** `lua/typst_templates.lua` (plain module), global `<leader>ln` / `:TypstNew [name]`, is a Telescope picker over Typst Universe's `packages.typst.org/preview/index.json` (latest version of each package with a `template` table; cached a day at `stdpath("cache")/typst/index.json`, refreshed in the background) plus local packages with a `[template]` in `<data>/typst/packages/local/*/*/typst.toml`. `M.favourites` sort first (★). Choosing one runs `typst init <spec> <dir>` (parents are created first, since `typst init` won't; non-empty dirs are refused), opens `template.entrypoint` and starts the live preview. Templates whose `compiler` is newer than the installed typst are marked ✗. **Snippets:** `lua/snippets/typst.lua` mirrors the TeX triggers but detects math with **treesitter** (a `math` node, cursor strictly between its `$`s, not inside a `string`; `get_node` at column 0 returns the root, so it retries at the cursor). Rules: no snippet for what Typst math already does natively (`->`, `<=`, `!=`, `...`, `oo`, `RR`, `x/y`), and no math autosnippet may be a prefix of or contained in a native name (`delta`, `sqrt`, `liminf`, `parallel`, `odot`...). That's why `del`/`sq`/`lim`/`compl`/`par`/`dot`/`inn` are absent and limits/sums are Tab snippets. Symbol names are typst 0.15's (`partial`, not `diff`; `product`, not `prod`; `chevron.l`, not `angle.l`), so compile any new expansion before adding it. In `fmta`, a literal `>` is `>>` (`lim_(<> ->> <>)`). The buffer goes to `typst compile -` on stdin with `cwd` = the file's dir: typst puts stdin **at the project root** (default: cwd), so relative imports resolve exactly as `typst compile foo.typ` would, but `../` imports escape the root and fail, also exactly as with the CLI's default root.

### PDF viewer

`lua/pdfview/` (a plain module; `require("pdfview").setup()` in `lua/defaults/init.lua` only claims `*.pdf` via `BufReadCmd` and sweeps stale caches) draws PDFs inside Neovim with kitty graphics. It is used by the LaTeX preview (`kind = "tex"`, a nofile split), the Markdown preview (`kind = "md"`, same split), the Typst preview (`kind = "typst"`, same split) and for any opened `.pdf` (`kind = "file"`, `buftype=nowrite` so sessions keep it). Files: `render.lua` (rasterising + caches), `viewer.lua` (one object per buffer: navigation, zoom, spread, search, links, highlights, keymaps), `tex.lua` (VimTeX/SyncTeX), `live.lua` (compile-on-edit + text-matched sync, shared by `markdown.lua` and `typst.lua`), `store.lua` (per-PDF page/zoom/spread/colours in `stdpath("state")/pdfview.json`).

- **Pipeline:** pages are rasterised once per scale (`pdftoppm` writing **PPM**, not PNG: PNG compression made it ~250 ms vs ~45 ms per retina page), recoloured by ImageMagick (ink = `-negate -grayscale Brightness`, pixel-identical to `1 − min(R,G,B)` via `-separate -evaluate-sequence min` at half the cost) and stored as memory-mapped `.mpc` under `stdpath("cache")/pdfview/<pid>` (per process; dead pids are swept, 16-entry LRU). Each render then crops the viewport from those into one window-sized PNG plus highlight rectangles: about 0.15 s, versus about 0.6 s re-rasterising at retina sizes. `pdftoppm -x/-y/-W/-H` is **not** faster than a full page (poppler rasterises it all), so crops are only for pages above `max_pixels` (high zoom). The neighbouring view is prefetched. Single pages are placed with `-extent` and a negative offset; a blank-canvas composite costs about 0.1 s more, so it's only used for spreads. Caches are keyed on the PDF's mtime.
- **Sizing:** snacks sizes images by their DPI (`size / dpi * 96 * scale`) and never enlarges, so every PNG is window-sized and stamped `-density 1`. snacks then always "shrinks to fit", a no-op that keeps pixels 1:1 with cells, which inverse search and link clicks rely on. Use `winheight()`, not `nvim_win_get_height()`, which counts the winbar; `getmousepos().winrow` counts it too. The viewport is kept in **PDF points** (`vx`/`vy` on the "view" = one page or a spread), so zoom keeps the centre. The tex split is sized to the page aspect; pages aren't necessarily A4 (the user's `cas-dc` reports are 210×280 mm).
- **Colours:** in "theme", ink becomes the Normal fg and the paper becomes alpha (ink = 1 − min(R,G,B)). Raster figures keep their colours, using `<image>` boxes from `pdftohtml -xml -zoom 1`, run per page. The same run gives link geometry: an `<a href>` inside a `<text>` run, where `x.html#N` is an internal link to page N. Vector figures still recolour.
- **Search** uses `pdftotext -bbox` words (whole document, cached per mtime). Matches span word boundaries; a hit highlights whole words.
- **snacks conflict:** snacks.image also claims `*.pdf` (page 1 as a picture). `claim_from_snacks()` drops `pdf` from `Snacks.image.config.formats` before snacks' one-time setup and clears its `BufReadCmd *.pdf` if setup already ran. Every image buffer gets `filetype=image` from snacks, which is in cursorline's `skip_ft`. **snacks spinner bug:** a placement closed while still converting keeps its "loading" timer (the stop check ignores `closed`), which clears the `snacks.image` namespace every 80 ms. That wipes the replacement image and leaves "identify loading …" on screen. Quick re-renders (autosize + sync) hit it every time. `fix_snacks_spinner()` in `viewer.lua` wraps `Placement:close` to set `buf = -1`, one of the timer's stop conditions. Drop it once snacks fixes this upstream.
- **Sessions:** the preview's nofile window is closed on `PersistenceSavePre`, recorded in `g:Session_pdfview` and re-opened on `PersistenceSavePost` (unless exiting) and on `PersistenceLoadPost`.
- **Markdown preview (`markdown.lua`, `kind = "md"`, `<leader>pv` / `<leader>pF` in markdown buffers):** the buffer's text goes to pandoc on stdin (`-f gfm`, `--pdf-engine=typst`, `--template=md_styles/<style>.typ`), run in the file's directory so relative images resolve. **Pages are shaped to the split:** the width is `cols × config.markdown.column_pt` (text keeps its size and reflows on resize) and the height follows the window's pixel aspect, so fit-page fills the window and `j`/`k` flow screen to screen. A `WinResized`/`VimResized` that changes the shape re-renders. So unlike LaTeX, the md split is **not** autosized (`autosize` is tex-only). **Styles:** `md_styles/` holds one pandoc typst template per look (`github` — github-markdown-css: SF NS / SF NS Mono, h1/h2 rules, code panels, gridded zebra tables — plus `book`, `article`, `swiss`, `editorial`, `terminal`), listed in `STYLES` in `markdown.lua`. `M.style(src)` resolves picker trial → per-file `style` in the store entry keyed by the `.md` path → the `_markdown` default entry → `config.markdown.style`. `store.save()` keeps an entry's non-view fields, and `_`-prefixed keys are never pruned. `<leader>ps` / `:MarkdownStyle[!] [name|-]` (`md_picker.lua`, Telescope): its previewer's `define_preview` calls `try_style` so moving the selection re-renders the open split; `<CR>` = file, `<C-d>` = default (and drops the file's pick), `<Esc>` reverts. Keep every template light-theme and distinct by type/weight/rules, not hue, because the viewer recolours ink. A literal `$` in a template comment must be `$$` (pandoc substitutes `$var$` everywhere), and a backtick inside typst markup starts raw — use a string (`text("`")`). GFM, not pandoc's own Markdown, so heading ids match the `#anchors` READMEs link to. `pandoc_filter.lua` (a **pandoc** Lua filter, never `require`d) fixes what typst would drop or refuse: `<div|p align="center">` regions are wrapped in `#align(center)`; raw HTML blocks are parsed as HTML (`<table>`, `<img>`); inline tag _pairs_ (`<sub>`, `<b>`, `<kbd>`, `<a href>`, …) become typst markup, and unmatched tags are dropped so brackets stay balanced; `<br>`/`<img>` are converted; Markdown table headers are bolded; and remote images are fetched with curl into `<pid>/img` (this pandoc has no HTTP; failures are remembered for the session). Missing local images and links to nonexistent anchors become text, because typst aborts the whole document on either. It renders on `TextChanged`/`TextChangedI`/`BufWritePost`, debounced by `config.markdown.delay`. The PDF is written to `*.tmp.pdf` and renamed into place, so the viewer never reads a half-written file. There's no SyncTeX here, so both directions **match text**. Forward strips the markup from the cursor line and finds the word sequence in `pdftotext` words; inverse takes the clicked word plus neighbours and finds them in the buffer's word stream. Ties go to the closest relative position. Both sides drop words that normalize to nothing (`%`, `—`) so the streams line up. Errors show as the winbar status. Per-file memory is keyed by the `.md` path (`store_key`), because the PDF lives in the per-process cache.
- **Live previews (`live.lua`):** `live.new(spec)` returns a preview module (`view`/`toggle_live`/`sync`/`inverse`/`refresh`/`compile`) with its own viewer and state; a backend only gives `kind`, `config`, `words(line)` (visible normalized words of a source line, for text-matched sync) and `command(P, src, dir, tmp)` (argv writing the PDF to `tmp`; stdin = buffer, cwd = file dir). Markdown adds page shaping + its resize autocmd; Typst is ~50 lines. Edits are **throttled, not debounced** (the first edit arms a `delay` timer, later ones ride along), so the preview keeps up while typing; compile and render each coalesce. After a recompile the sync is the only render, so `sync()` **always** renders, even when the cursor line can't be placed (`#set` lines, half-typed words, math). Otherwise the old page stays up. It also calls `V:warm()` to rasterise the visible pages while `pdftotext` runs. `V:fixed_pages()` (tex, typst) decides whether the split autosizes to the page.
- **Typst preview (`typst.lua`, `kind = "typst"`, `<leader>lv`):** `typst compile --diagnostic-format short - tmp.pdf`, debounced by `config.typst.delay`. `plain_words` drops `#set`/`#show`/`#let`/`#import` lines, comments, inline math, labels and `@refs`, and `#func(args)` heads (keeping the `[body]`).
- **Integrations:** the viewer is source-agnostic. A preview passes `integration` (a module with `live`/`toggle_live`, enabling the `z`/`f` keys), `inverse` (defaults to SyncTeX), `title` and `store_key` to `V.new`. `status` is `{ kind = "error"|"busy", text }`. Sessions handle all previews (`g:Session_pdfview = {tex=…, md=…, typst=…}`).
- It deliberately does not use image.nvim, whose global `max_height = 12` (sized for Molten) would clip a page.

## Adding a plugin

Create a new file in `lua/plugins/` returning a lazy.nvim spec:

```lua
return {
  "author/plugin-name",
  opts = { ... },
}
```

lazy.nvim auto-imports everything under `lua/plugins/`.

## External dependencies

- `lazygit` binary (for lazygit.nvim)
- `gh` CLI, authenticated (`gh auth login`) — optional; powers the dashboard's GitHub stats line (PRs, issues, contributions, streak) and upstream.nvim (`<leader>G`). Without it the stats line simply doesn't render.
- `make` (for telescope-fzf-native)
- `claude` (Claude Code CLI), logged in — for the writing companion (quill.nvim, `<leader>W`), which runs `claude -p` headless with your plan
- Zotero 7+ with the Better BibTeX add-on, plus `sqlite3` and `curl`, for ibid.nvim (`<leader>Z`); citing/completion/hover work with Zotero closed, syncing newly cited keys needs it running
- `claude` (Claude Code CLI), logged in — for the writing companion (`lua/writing/`, `<leader>W`), which runs `claude -p` headless with your plan
- `cppman` (`pipx install cppman`) and `groff` (`brew install groff`) for C++ references (`lua/refdocs/`); `cppman -c` caches all of cppreference offline
- `poppler` (`pdftoppm`, `pdfinfo`, `pdftohtml`, `pdftotext`) and ImageMagick (`magick`), both via Homebrew, for the in-terminal PDF viewer (`lua/pdfview/`); plus `pandoc` and `typst` (`brew install pandoc typst`) for its Markdown preview; `typst` alone for the Typst preview (tinymist bundles its own compiler for LSP/export)
- An `nvim()` zsh wrapper in `~/.zshrc` (not in this repo) — optional; sets `$NVIM_CWD_FILE` so `lua/defaults/shell_cwd.lua` can write Neovim's final cwd on exit and the shell `cd`s there (cd-on-quit, e.g. after the dashboard's `d` directory picker). The module unsets the var so `:terminal` shells don't inherit it.
- `~/.virtualenvs/neovim` venv with `pynvim`, `jupyter_client` (Neovim Python host / Molten), and `uv` with `uv tool install jupytext` (jupytext.nvim)
- `uv` — runs an ephemeral `ipykernel` over a project venv that lacks one (`lua/notebook/kernel.lua`), and installs `jupytext`
- `~/.local/bin/jkernel` — optional now; registers venvs as global Jupyter kernels (see `:help nvim-notebooks-jkernel`). Not part of this repo.
- A Kitty-graphics terminal (kitty, the usual one; WezTerm/Ghostty) for inline images (Molten plots, the PDF viewer, music art); Alacritty works for everything else
- `r` and `quarto` (both via Homebrew: `brew install r quarto`) for R/Quarto (`.qmd`) support
- R package `languageserver` for the `r_language_server` LSP (Mason's `r-languageserver` installs its own bootstrapped R environment, so a system-wide `install.packages("languageserver")` isn't strictly required, but is a fallback if Mason's bootstrap fails)
- R package `IRkernel` (`install.packages("IRkernel"); IRkernel::installspec()`) registers R as a Jupyter kernel for Molten — a one-time, machine-wide step, unlike Python's per-project `jkernel` venv registration; `jkernel` itself is Python-venv-specific and does not handle R
