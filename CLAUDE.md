# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

Opinionated Neovim config written in Lua using `lazy.nvim` as the plugin manager. Targets macOS, primarily run in Alacritty (inline notebook images require a Kitty-graphics terminal instead — see Molten / notebooks).

## Architecture

### Load order
`init.lua` → `lua/defaults/init.lua` → options, keymaps, lazy bootstrap, colorscheme restore → all plugin specs under `lua/plugins/`

### Key separation
- `lua/defaults/` — core Neovim settings (not plugin-specific): options, keymaps, lazy bootstrapping, and LSP server setup (`lsp.lua`)
- `lua/plugins/` — one file per plugin (or tightly related group), each returning a lazy.nvim spec table

### Colorscheme
The last used colorscheme is persisted to `stdpath("state")/colorscheme` (machine-local, **not** in the repo — `.colorscheme` is gitignored and only read once as a legacy migration) and restored on startup via `lua/defaults/init.lua`. Any `:colorscheme` call triggers an autocmd that writes the name to that file. The startup load is wrapped in `pcall` and falls back to `kanso`, so a missing/uninstalled scheme never aborts startup. `<leader>cs` opens Telescope with live colorscheme preview.

Installed schemes (one file each under `lua/plugins/`): catppuccin, kanagawa, kanso, lackluster, nightfox, everforest, melange, gruvbox-material, zenbones (+ its variants forestbones/neobones/kanagawabones/seoulbones). Warm set: rose-pine (`name = "rose-pine"`), kanagawa-paper, bamboo, flexoki (`name = "flexoki"`; no transparency option, relies on the strip autocmd), evergarden, vesper (dark only). **evergarden sets `'background'` from its variant**, so its spec chooses the variant (`fall`/`summer`) from `vim.o.background`; bamboo's colors file resets its modules on every load, but its options live in `vim.g.bamboo_config` so they survive. The palette leans earthy (grays/greens/browns), minimalist, with dark and light variants.

**Transparency:** by default every colorscheme renders with no editor background so the Alacritty background shows through. This is enforced two ways, both gated on `vim.g.ui_transparent`: native `transparent` options are set per-plugin where supported (each theme spec passes `vim.g.ui_transparent`, never a literal `true` — keep that when adding a theme), and a global `ColorScheme` autocmd in `lua/defaults/init.lua` (`transparent_groups`) strips the bg of core groups after any scheme loads — covering schemes without a transparency option (e.g. melange) — and returns early in solid mode. Add new groups to that list if a plugin leaves a background.

**Toggles (`lua/defaults/ui_toggle.lua`):** `<leader>ub` / `:ToggleTransparency` flips transparent ↔ solid, `<leader>uB` / `:ToggleBackground` flips `'background'` dark ↔ light. State persists to `stdpath("state")/ui.json` and `restore()` runs **before** `require("defaults.lazy")` because the theme specs read the flag in `setup()`. A toggle finds the active theme's lazy plugin by locating `colors/<name>.{lua,vim}` on the runtimepath (no hand-kept name→plugin table), re-runs its `init`/`config` (nightfox/catppuccin hash options and recompile on change), and reloads the scheme. Going light while transparent forces solid (light text over the dark terminal is unreadable) and going dark restores it; `toggle_background()` clears `g:colors_name` before setting `'background'` (otherwise Neovim auto-reloads the scheme with its *old* config, which variant-driven schemes like evergarden flip straight back), and a scheme with no variant for the target — pins `'background'` back (nightfox, lackluster) or ignores it and keeps drawing dark (vesper; detected by `Normal` bg/fg luminance) — is undone completely, `'background'` included, with a warning. Inside Alacritty (`$ALACRITTY_SOCKET`), solid mode sets `window.opacity=1` live via `alacritty msg config`, and transparent mode / `VimLeavePre` run `--reset` to restore `alacritty.toml`'s value.

**UI chrome (`lua/defaults/options.lua`):** a few options keep the UI clean against the transparent background. `fillchars` blanks the end-of-buffer `~` and uses a thin `│` window separator. The `cursorline` is owned by `lua/defaults/cursorline.lua` (required from `defaults/init.lua` *after* the strip autocmd so its `ColorScheme` handler runs second): it is on only in the focused regular-file window and explicitly **off** in terminals, floats (Zen), and `skip_ft` filetypes, because window-local options are copied into new windows; neo-tree is `unmanaged_ft` (its cursorline is the selection marker); `w:no_cursorline` opts a window out. In transparent mode the default style is number-only (accent bold `CursorLineNr` from the scheme's `Function` fg, `cursorlineopt=number`); `<leader>uc` cycles number → underline (single-colour `sp`) → band (blended tint). Highlights use `nvim_set_hl` (replace, not merge). Solid mode leaves the scheme's own cursorline band alone. Accent/blend helpers live in `lua/defaults/colors.lua` — reuse them for any theme-derived accent instead of hardcoding colours. `pumblend`/`winblend` give the popup menu and floats slight transparency. Diagnostics use icon signs (via `vim.diagnostic.config`) instead of the default `E`/`W`/`I`/`H` letters.

### Aesthetics & ambience
A layer of plugins exists purely for a pleasant feel (one file each under `lua/plugins/`):
- **`snacks.lua`** — enables the snacks `dashboard` and `scroll` modules (snacks itself comes in via `claudecode.nvim`). The dashboard is a **minimal single column**, everything centered, and **transparent** — its `SnacksDashboardNormal` group is in the `transparent_groups` list in `lua/defaults/init.lua`. Sections: header art (read verbatim from `dashboard-header.txt` in the config root if it exists, else a built-in Python snake; `dashboard.width` = the art's widest line, floor 60), a **live clock** + date, a **GitHub stats line** (open PRs · issues · contributions · streak), and a **one-line key hint**. The `keys` table drives both the hint (entries with `hint`) and the bindings (every entry as a `hidden = true` item), so g/n/p/l/m stay bound without rows — add keys there, not as separate sections. The clock is a uv timer aligned to the minute that only runs while a `snacks_dashboard` window is visible (started on `SnacksDashboardOpened`/`BufEnter`, stopped on leave). Colors are `DashboardMuted` (Comment fg) plus one `DashboardAccent` (scheme `Function` fg via `lua/defaults/colors.lua`), re-applied on `ColorScheme` — no hardcoded palette.
- **`lua/defaults/dashboard_data.lua`** — the async/cached data layer behind the stats line. **One** `gh api graphql` request (authenticated `viewer`, no hardcoded username) returns the contribution calendar plus `search { issueCount }` for open PRs and issues — exact counts, unlike `gh search … -q length`, which is capped at gh's default limit of 30. The streak is computed from the calendar's `date`s against the local date (today may be empty; days after today are ignored). The result is written to `stdpath('cache')/dashboard/stats.json` with a 30-min TTL; the section reads the cache instantly (never blocking startup) and a debounced `Snacks.dashboard.update()` refreshes when the fetch returns. `setup({ issues = "assignee" | "author" })` picks which issues count (default: assigned; the cache is keyed on it). No `gh`/not authed → no cache → the line is hidden.
- **Fades vs. transparency:** a terminal cell is either a solid colour or the terminal bg, so anything that fades over a transparent editor needs to be told what colour is behind it. That colour is `require("defaults.colors").terminal_bg` (Alacritty's default `#181818`; `alacritty.toml` sets none) — used by **`smear_cursor.lua`** (`transparent_bg_fallback_color`; also stiffer than default) and **`tiny-glimmer.lua`** (flash on yank, `transparency_color`; only yank is on, so `p`/`n`/`u` aren't hijacked). Prefer motion over opacity for new animations: nvim-notify uses `slide`, not `fade`. snacks.scroll is 140ms outQuad (50ms for held-key repeats); mini.indentscope's guide grows out over 80ms.
- **`colorizer.lua`**, **`rainbow-delimiters.lua`**, **`tiny-devicons.lua`**, **`satellite.lua`** (scrollbar with git/diagnostic/search marks), **`illuminate.lua`** (word-under-cursor), **`precognition.lua`** (motion hints), **`cellular-automaton.lua`** (fun screensaver), **`typr.lua`** (typing practice + stats, via `nvzone/volt`).

When adding cursor/scroll-animating plugins, check this list first — multiple plugins animating the same thing will conflict.

### LSP
Two-layer setup:
- `lua/plugins/mason.lua` ensures the servers are installed via mason-lspconfig (`clangd`, `pyright`, `ruff`, `ts_ls`, `html`, `cssls`, `emmet_language_server`, `texlab`, `tinymist`, `lua_ls`) and configures them through Neovim 0.11's native API: shared cmp capabilities go on `vim.lsp.config("*")`, per-server overrides (capabilities/settings/filetypes/on_attach) live in the `servers` table and are applied with `vim.lsp.config(name, opts)`, and mason-lspconfig v2's `automatic_enable` calls `vim.lsp.enable` for each installed server (v2 has no `handlers` option — don't reintroduce one, and register configs *before* `mason-lspconfig.setup()`) — `clangd` pins utf-16 offset encoding, `pyright` defers import-organizing to `ruff`, `ruff` drops its hover so it doesn't duplicate pyright, `tinymist` formats with typstyle and exports `foo.pdf` on save. The same file also registers **mason-tool-installer** to guarantee the non-LSP tools conform/dap call by name (`black`, `isort`, `stylua`, `clang-format`, `latexindent`, `typstyle`, `prettier`, `codelldb`, `debugpy`).
- `lua/defaults/lsp.lua` is a single global `LspAttach` autocmd that binds buffer-local keymaps (`gd`/`gD`/`gr`/`gi`/`gy`/`<leader>rn`/`<leader>ca`/`[d`/`]d`) for **any** attached server, and enables inlay hints (toggle `<leader>uh`) when the server supports them. It is `require`d from `lua/defaults/init.lua`. Do not add per-server `on_attach` keymaps — extend this autocmd instead. `K` is deliberately **not** bound there: its single owner is `lua/plugins/ufo.lua` (peek fold → hover.nvim, which includes the LSP provider), and a buffer-local map would shadow it.

`lua/plugins/lsp.lua` just pulls in `nvim-lspconfig`. Add new LSP servers to `ensure_installed` (and `servers` for overrides) in `mason.lua`.

A `.luarc.json` at the config root configures lua_ls for this repo: it declares `vim` and `Snacks` as globals so editing the config produces no spurious "undefined global" warnings (LuaJIT runtime, third-party checks off). Add to its `diagnostics.globals` if another runtime global trips lua_ls.

### Project settings (projectrc.nvim)
`lua/plugins/projectrc.lua` loads **projectrc.nvim**, a standalone plugin developed in `~/Downloads/GitHub/projectrc.nvim` (`dir =` spec, `lazy = false` because its appliers must see the first FileType; its own README and `:help projectrc` are the reference). It keeps VS Code–style per-project settings in `.nvim/settings.json` (flat dotted keys + `"[ft]"` overrides), edited in a float (`<leader>,` / `:ProjectRC`, tabs Editor/Format/LSP/Build/Debug), and stores settings other tools read in **their** files (`.clang-format` keys edited in place, a marked fragment in `.clangd`). Settings that run something are ignored until the file is trusted in the 'exrc' hash db. The plugin also makes **C-family indent follow clang-format** (`clang-format --dump-config` → `shiftwidth`/`tabstop`/`expandtab`; without a `.clang-format`, `--style=<fallback_style>`, LLVM + IndentWidth 4), so `>>` and format-on-save agree. **No `require` of this config from the plugin**: the glue lives in the spec file and calls the plugin's public API: theme colours through `defaults/colors.lua` (`ProjectRCAccent`/`Title`/`Muted`/`Warn`/`Sel`, re-applied on `ColorScheme`; the plugin's groups are `default` links), `transparent = g:ui_transparent`, and a `runner` that sends build/run/test (`<leader>bb/br/bt`) to one shell per project through `lua/terminals` (so `<leader>tq` works). Hooks in other specs: conform (`format_opts()` in `format_on_save`/`<leader>cf`, `clang_format_args()` as clang_format's `prepend_args`), mason's clangd `cmd = projectrc.clangd_cmd` (`--query-driver`), dap (`dap_sync()`). The float's filetype `projectrc` is in cursorline.lua's `unmanaged_ft`.

### Buffer-centric quitting
`lua/defaults/bufclose.lua` (required from `keymaps.lua`) makes `:q` close the **buffer**, not Neovim. It is wired as a command-line `<CR>` `expr` mapping that rewrites a whole-line `q` / `q!` / `wq` / `wq!` to `:BufQuit[!]` / `:BufWriteQuit[!]` — **not** `:cabbrev`: a `q` abbreviation doesn't expand when `!` follows, and a `q!` abbreviation never matches, so `:q!` would still exit. `:quit`, `:qa`, searches and `<cmd>q<cr>` inside mappings are untouched. In a split / float / neo-tree / multi-tab, BufQuit is a plain `:quit`; in the last editing window (floats and neo-tree don't count) it switches to the next listed buffer (files before terminals, then MRU) or opens the dashboard **in that window** (`Snacks.dashboard.open({ buf, win })` — without `win` snacks opens a float), and `:q` on that dashboard runs `:qall`. Terminal/unlisted buffers are only hidden (jobs survive); modified buffers prompt Save/Discard/Cancel. `<leader>x` calls the same `close_buffer()`.

### Claude chats in buffers
`lua/claude_chats/` (not a lazy spec — a plain module) runs `claude` in ordinary terminal buffers, any number at once, as an alternative to claudecode.nvim's single split. Each buffer gets the same env claudecode gives its own terminal (`ENABLE_IDE_INTEGRATION`, `CLAUDE_CODE_SSE_PORT` from `claudecode.server.init`'s port, loopback `no_proxy`), so IDE features keep working. New chats are spawned with a pre-generated `--session-id` and tagged `b:claude_chat`, which is how running buffers are matched to their session logs. Past sessions are read from `~/.claude/projects/<cwd with non-alnum → "-">/*.jsonl`; titles come from `custom-title` > `ai-title` > `last-prompt` lines (tail of file, cached by mtime). `claude_chats/neotree/` is a custom neo-tree source (`name = "claude"`) registered in `sources` in `lua/plugins/neo-tree.lua` (its tab icon/name, like every source's, lives in `lua/neotree_tabs.lua` — the selector shows icons only and bufferline's neo-tree offset shows the active source's name, both from that one table; keep glyphs as BMP `\u{}` escapes); its commands module overrides neo-tree's filesystem-mutating commands because chat nodes carry the `.jsonl` as `path` (stock `delete` would remove the log).

### Terminals
`lua/terminals/` (a plain module, like `claude_chats`) owns terminal sessions; `lua/plugins/toggleterm.lua` only draws the windows and forwards toggleterm's `on_create`/`on_open`/`on_exit` to it, then calls `require("terminals").setup()`. **Ids are partitioned:** shells 1–99 (`new()` takes the first free id), the pinned REPLs 100+ (`M.repls`) — toggleterm hands out the lowest free id from one pool, so never create a terminal without an explicit id. Per-terminal state (`info(id)`: custom name, cwd, running command, last command, exit, output rows, unseen) is fed by **zsh prompt hooks**: shells get `ZDOTDIR=shell/zsh` (+ the real one in `NVIM_TERM_ZDOTDIR`), whose `.zshenv` restores the user's ZDOTDIR, sources their files unchanged, and (interactive only — toggleterm runs `zsh -c "zsh;#toggleterm#N"`, so the outer non-interactive zsh must keep pointing at the wrapper) emits OSC `633;E;<cmd>`, `133;C`, `133;D;<status>` and `7`, read through the `TermRequest` autocmd. The cursor rows at C/D are the first output row and the row after the output (1-indexed), which `quickfix()` uses (with a `%D` line in the errorformat so paths resolve against the shell's cwd). "Last used" is set only by `on_open`/`TermEnter`, **not** `BufEnter` (toggleterm moves focus through other terminal windows while closing). State changes fire a debounced `User TermsChanged`, consumed by the winbar (`winbar_label`, toggleterm's per-terminal `name_formatter`) and the neo-tree source `terminals/neotree/` (`name = "terminals"`, tab in `lua/neotree_tabs.lua`). Python paste: 3.13+ (pyrepl) gets bracketed paste and a **separately delayed** second Enter (pyrepl reads a fast burst as more paste); older REPLs get blank lines stripped. Sessions: `persistence.lua` stores `session_state()` as JSON in `g:Session_terminals` and `session_restore()` re-spawns them.

### Music
`lua/music/` (a plain module, `require("music").setup()` in `lua/defaults/init.lua`) controls the **Apple Music app**; Neovim plays no audio. `applemusic.js` (JXA, `osascript -l JavaScript applemusic.js <cmd>`) answers every command with one JSON line, and state-changing commands return the fresh poll so the UI updates at once. It checks `Application("Music").running()` **before touching any property**, because any property access launches Music. Track lists use bulk reads (`tracks.name()`: one Apple Event per field, not per track), so the whole library takes ~170 ms. `artwork.applescript` writes a track's raw art to `<id>.dat` (not `.raw`, which magick reads as camera RAW), and magick turns it into a 512px PNG at `-density 1` (see PDF viewer › Sizing) in `stdpath("cache")/music`. `init.lua` holds `M.state` and polls on an adaptive one-shot timer (1 s with the player open, 3 s playing, 5 s paused, 15 s with Music closed, plus `FocusGained`). `M.position()` interpolates between polls, so **the lualine component (`lualine_x`) only reads cached state** and never shells out. Changes fire `User MusicChanged`, which refreshes lualine. `vim.system` has an 8 s timeout, because Apple Events block for up to 2 minutes while macOS shows its Automation prompt. Error `-1743` (permission denied) stops polling. After a command that answers mid-transition (no track yet), it re-polls after 600 ms. `ui.lua` is a library browser float above a now-playing card. The browser has tabs Playlists/Artists/Albums/Songs/Queue, with one item per line so `j`/`k`/`G` work natively. Per-tab drill-down stacks, the cursor and the filter live in module state, so they survive closing the player. The selection is the float's own cursorline, so `music` is in cursorline.lua's `unmanaged_ft`. The album art is a third, borderless float (`relative = "win"`, zindex 51) over the card's left padding, because `Snacks.image.buf.attach` draws over a whole buffer. **All the floats set `winblend = 0`:** kitty locates an image by its placeholder cells' fg colour, and the global `winblend = 10` blends that colour, so the art silently doesn't draw. It uses pdfview's exported `fix_snacks_spinner()`. **Cover grids:** album and playlist views (`grid = true`) render as tiles (7 rows of art, a title and a subtitle) when `Snacks.image.supports_terminal()`; otherwise they're lists. Each cover is a snacks *inline* placement with `conceal = true` and a `range` spanning the art rows. That is the code path where snacks overlays each image row at a fixed `virt_text_win_col`, so covers sit side by side and scroll as text. The list window therefore keeps `conceallevel = 0`. In grid mode `v.cursor` is the tile index, not a line. Caption byte ranges are recorded at build time, because titles with accents or Cyrillic make bytes ≠ cells. Scrolling snaps to whole tile rows, which needs window-local `scrolloff = 0` (the global 8 re-scrolls). The list height is a whole number of tile rows. A re-render bumps `ui.gen`, so covers arriving for an old layout are dropped. `music.artwork()` runs at most 3 exports at once; `urgent` (the now-playing card) jumps the line. A playlist's cover is its first song's art (`first` from the `playlists` command). `library.lua` dumps every track once (`library` command, ~190 ms) and groups albums (album artist + album, sorted by disc/track) and artists locally. "Play album/artist" and `a` go through a **`Neovim Queue` user playlist** (`queue_set`/`queue_add`), because Music has no play-album command and Up Next isn't scriptable. Each track is found with its own `whose({persistentID})` (~12 ms). A bulk `persistentID()` read plus `tracks[i]` copies the **wrong songs**, because the bulk order doesn't match element indexing. Create playlists with `Music.make`; `userPlaylists.push` fails with "Can't convert types". Highlights `MusicAccent`/`MusicTitle`/`MusicMuted`/`MusicSel` come from `defaults/colors.lua`. Keys live under `<leader>M`, because `<leader>m` is Molten.


### GitHub (upstream.nvim)
`lua/plugins/upstream.lua` loads **upstream.nvim**, a standalone plugin developed in `~/Downloads/GitHub/upstream.nvim` (`dir =` spec; its own README and `:help upstream` are the reference). It is a full-screen GitHub float on the `gh` CLI (issues, PRs, review requests, Actions runs; manage, compose buffers where `:w` submits, PR review with a pending review, Claude drafts for PR bodies and review comments). **No `require` of this config from the plugin**: the glue is all in the spec file. Theme colours go through `defaults/colors.lua` (`UpstreamAccent`/`Title`/`TabActive`/`Muted`/`Sel`, re-applied on `ColorScheme`; the plugin's own groups are `default` links, so these win). `ai.open_chat` opens "work on this issue" chats through `claude_chats.open({ prompt = … })`, where `prompt` is passed as claude's positional argument. `User UpstreamChanged` with `data.item` (a write) forces a `dashboard_data.refresh(true)`. The list's filetype `upstream` is in cursorline.lua's `unmanaged_ft`. The dashboard's hidden `G` key runs `:Upstream`. Compose buffers are `acwrite` and open in the current window, so `:q` on an unsent one goes through bufclose's Save/Discard/Cancel (Save = submit).
### Molten / notebooks
`molten.nvim` runs code in Jupyter kernels and `jupytext.nvim` handles `.ipynb` ↔ markdown conversion. Requires `:UpdateRemotePlugins` after install.

**Python host:** Neovim's Python provider points at a dedicated venv `~/.virtualenvs/neovim` (set via `vim.g.python3_host_prog` in `lua/defaults/init.lua`) that holds `pynvim`, `jupyter_client`, and `jupytext` (plus optionally `pillow` for `:MoltenImagePopup`, `nbformat` for import/export, `cairosvg` for SVG). Homebrew's python3 is PEP-668 externally-managed, so deps aren't installed there. That venv's `bin` is prepended to `PATH` so `jupytext.nvim` (which calls a bare `jupytext`) resolves. Notebook kernels are separate per-project venvs registered with `jupyter kernelspec`.

**Kernels (`lua/molten_kernels.lua`, a plain module):** you pick an *interpreter*, as in VS Code; no `jkernel add`. Molten only starts kernelspecs (via `jupyter_client.find_kernel_specs()`), so for the chosen interpreter the module writes one to `stdpath("data")/molten/kernels/nvim-<env>-<hash>/` and runs `:MoltenInit <name>`. That dir is prepended to `$JUPYTER_PATH` by `setup()`, called from molten.lua's `init`, because **the Python host reads it from its own env at spawn**, so it must be set before anything starts the host. ~/Library/Jupyter is never touched. A spec is per (interpreter, notebook dir): its argv is `python -c "os.chdir(argv.pop(1)); runpy ipykernel_launcher" <dir> -f {connection_file}`, because Molten starts kernels in the host's cwd, not the notebook's; its `env` puts the env's bin first on `${PATH}` (+ `VIRTUAL_ENV`/`CONDA_PREFIX`). Discovery only stats files (pyvenv.cfg, conda-meta, ~/.virtualenvs, conda's environments.txt, pyenv, uv, poetry/pipenv caches, system); the interpreter is run once on selection to probe version, ipykernel and PEP 668 (externally managed → offer to create `.venv`; missing ipykernel → confirm, then `uv pip`/`pip`). `ensure(buf, cb)` is what every evaluation key calls: attached kernel, else remembered (per file, then per project root, in `stdpath("state")/molten_kernels.json`), else the only project venv (or the only registered kernel of the buffer's language, for R `.qmd`), else the Telescope picker (`<leader>mi` / `:Kernel [path]`). Picking replaces the attached kernel (`MoltenDeinit` first); `<leader>mI` is raw `:MoltenInit` for adding a second one. Registered kernels (IRkernel, `jkernel`) are listed after the interpreters. `b:molten_kernel` (cleared on `MoltenDeinitPost`) feeds a lualine component, so drawing never calls into the host. Bulk runs (`<leader>ra/rk/rj`) pass the kernel id explicitly and skip cells whose fence language isn't the kernel's. Full workflow in [`docs/molten.md`](docs/molten.md).

**Images / terminal:** inline image output (plots) only works in terminals speaking the Kitty graphics protocol (Kitty/WezTerm/Ghostty). `lua/plugins/molten.lua` detects the terminal at startup: in a capable terminal it uses `image.nvim` (loaded via `cond`); otherwise (e.g. **Alacritty**, the current terminal) it sets `molten_image_provider = "none"` and relies on virtual-text output. View plots externally with `<leader>oi` (`:MoltenImagePopup`) or `<localleader>mx` (`:MoltenOpenInBrowser`).

**Quarto / R:** `.qmd` files get per-language LSP-in-chunks via `quarto-nvim` + `otter.nvim` (`lua/plugins/quarto.lua`, `ft = "quarto"`, `codeRunner.enabled = false`); `.qmd` is registered as filetype `quarto` defensively in `lua/defaults/init.lua`. Execution does **not** go through quarto-nvim's own runner — it reuses Molten exactly like Python: register R as a Jupyter kernel via IRkernel (`install.packages("IRkernel"); IRkernel::installspec()`, a one-time machine-wide step, unlike per-project `jkernel` venvs), then pick it from `<leader>mi`. `molten_cells()` in `lua/defaults/keymaps.lua` matches both plain jupytext fences (` ```python `) and Quarto's curly-brace chunk headers (` ```{r} `, ` ```{python} `), so `<leader>rc`/`ra`/`rk`/`rj` work unchanged in `.qmd`. `<leader>tR` opens a persistent R REPL terminal (same `named_term` pattern as `<leader>tp`/`<leader>tN`). `<leader>op`/`<leader>oP` (`:QuartoPreview`/`:QuartoClosePreview`) run a live-reload document preview in a browser. Full workflow in [`docs/molten.md`](docs/molten.md#r--quarto).

### LaTeX
Five layers, all of which hang off VimTeX initialising correctly:
- **`lua/plugins/vimtex.lua`** — VimTeX itself, `lazy = false` (its ftplugin must register before the first `.tex` buffer). **Pinned to `tag = "v2.18"`**: VimTeX HEAD raised its floor to Neovim 0.12.4 on 2026-07-22, and on an older Neovim the version gate `finish`es `ftplugin/tex.vim` *before* `vimtex#init()` — killing every mapping, the latexmk compiler, and `vimtex#syntax#in_mathzone()`. Drop the pin once Neovim is 0.12.4+.
- **In-terminal preview: `lua/pdfview/tex.lua`** (`<leader>lv`, also visual; `<leader>lF` live follow). It builds on the PDF viewer (see **PDF viewer** below). Forward search runs `synctex view` once per line, and the `h/v/W/H` boxes become accent highlights. Inverse search maps the clicked page point to `synctex edit -o page:x:y:pdf`. Paths need `simplify()` because synctex reports `dir/./file`. The PDF comes from `b:vimtex.compiler.get_file('pdf')`; v2.18 has no `b:vimtex.out()`. `VimtexEventCompiling`/`CompileFailed`/`CompileSuccess` set the winbar status. Success with `config.follow` re-syncs to the cursor. Outside a graphics terminal it falls back to `:VimtexView`.
- **External viewer: Skim** (`<leader>lV`) (`vimtex_view_method = "skim"`, sync/activate/reading-bar on). Not sioyek — sioyek ships unsigned, so Gatekeeper kills it, and Homebrew deprecated the cask (disabled 2026-09-01). VimTeX drives Skim over AppleScript/JXA, so macOS may prompt for automation permission on first use.
- **LSP/format** — `texlab` (mason `ensure_installed`) and `latexindent` for `tex` in conform.
- **Snippets** — `lua/snippets/tex.lua`, a Castel-style set loaded by LuaSnip's `from_lua` loader. Math-mode autosnippets gate on `vimtex#syntax#in_mathzone()`, so **they die silently whenever VimTeX fails to init** — check VimTeX first if snippets stop firing.

Treesitter highlighting is deliberately `disable`d for `latex` (`lua/plugins/treesitter.lua`) so VimTeX owns syntax + conceal; the parser stays installed for folding/textobjects/context.

Debugging tip: VimTeX starts viewers **detached**, so Skim failures are invisible inside Neovim (`<leader>lV` just does nothing). Run `<leader>li` (`:VimtexInfo`) and reproduce the printed viewer command in a shell, where stderr is visible.

### Typst
Neovim already detects `*.typ` as filetype `typst`. **tinymist** (mason) does LSP + formatting (`formatterMode = "typstyle"`, `exportPdf = "onSave"` writes `foo.pdf` beside `foo.typ`); conform also runs `typstyle`; treesitter highlighting stays **enabled** (nothing else owns Typst syntax). The preview is **not** typst-preview.nvim/a browser: it is `lua/pdfview/typst.lua`, a backend of the shared live preview (see **PDF viewer**), so `.typ` buffers get the same kitty split as LaTeX. Buffer-local maps in `lua/defaults/keymaps.lua` (`TypstKeymaps`) reuse the LaTeX keys: `<leader>lv` live preview (also visual), `<leader>lF` follow, `<leader>lk` close, `<leader>lo` compile once to `foo.pdf`, `<leader>lV` compile + open in the system viewer, `<leader>le` diagnostics loclist. **Templates:** `lua/typst_templates.lua` (plain module), global `<leader>ln` / `:TypstNew [name]`, is a Telescope picker over Typst Universe's `packages.typst.org/preview/index.json` (latest version of each package with a `template` table; cached a day at `stdpath("cache")/typst/index.json`, refreshed in the background) plus local packages with a `[template]` in `<data>/typst/packages/local/*/*/typst.toml`. `M.favourites` sort first (★). Choosing one runs `typst init <spec> <dir>` (parents are created first, since `typst init` won't; non-empty dirs are refused), opens `template.entrypoint` and starts the live preview. Templates whose `compiler` is newer than the installed typst are marked ✗. **Snippets:** `lua/snippets/typst.lua` mirrors the TeX triggers but detects math with **treesitter** (a `math` node, cursor strictly between its `$`s, not inside a `string`; `get_node` at column 0 returns the root, so it retries at the cursor). Rules: no snippet for what Typst math already does natively (`->`, `<=`, `!=`, `...`, `oo`, `RR`, `x/y`), and no math autosnippet may be a prefix of or contained in a native name (`delta`, `sqrt`, `liminf`, `parallel`, `odot`...). That's why `del`/`sq`/`lim`/`compl`/`par`/`dot`/`inn` are absent and limits/sums are Tab snippets. Symbol names are typst 0.15's (`partial`, not `diff`; `product`, not `prod`; `chevron.l`, not `angle.l`), so compile any new expansion before adding it. In `fmta`, a literal `>` is `>>` (`lim_(<> ->> <>)`). The buffer goes to `typst compile -` on stdin with `cwd` = the file's dir: typst puts stdin **at the project root** (default: cwd), so relative imports resolve exactly as `typst compile foo.typ` would, but `../` imports escape the root and fail, also exactly as with the CLI's default root.

### PDF viewer
`lua/pdfview/` (a plain module; `require("pdfview").setup()` in `lua/defaults/init.lua` only claims `*.pdf` via `BufReadCmd` and sweeps stale caches) draws PDFs inside Neovim with kitty graphics. It is used by the LaTeX preview (`kind = "tex"`, a nofile split), the Markdown preview (`kind = "md"`, same split), the Typst preview (`kind = "typst"`, same split) and for any opened `.pdf` (`kind = "file"`, `buftype=nowrite` so sessions keep it). Files: `render.lua` (rasterising + caches), `viewer.lua` (one object per buffer: navigation, zoom, spread, search, links, highlights, keymaps), `tex.lua` (VimTeX/SyncTeX), `live.lua` (compile-on-edit + text-matched sync, shared by `markdown.lua` and `typst.lua`), `store.lua` (per-PDF page/zoom/spread/colours in `stdpath("state")/pdfview.json`).
- **Pipeline:** pages are rasterised once per scale (`pdftoppm` writing **PPM**, not PNG: PNG compression made it ~250 ms vs ~45 ms per retina page), recoloured by ImageMagick (ink = `-negate -grayscale Brightness`, pixel-identical to `1 − min(R,G,B)` via `-separate -evaluate-sequence min` at half the cost) and stored as memory-mapped `.mpc` under `stdpath("cache")/pdfview/<pid>` (per process; dead pids are swept, 16-entry LRU). Each render then crops the viewport from those into one window-sized PNG plus highlight rectangles: about 0.15 s, versus about 0.6 s re-rasterising at retina sizes. `pdftoppm -x/-y/-W/-H` is **not** faster than a full page (poppler rasterises it all), so crops are only for pages above `max_pixels` (high zoom). The neighbouring view is prefetched. Single pages are placed with `-extent` and a negative offset; a blank-canvas composite costs about 0.1 s more, so it's only used for spreads. Caches are keyed on the PDF's mtime.
- **Sizing:** snacks sizes images by their DPI (`size / dpi * 96 * scale`) and never enlarges, so every PNG is window-sized and stamped `-density 1`. snacks then always "shrinks to fit", a no-op that keeps pixels 1:1 with cells, which inverse search and link clicks rely on. Use `winheight()`, not `nvim_win_get_height()`, which counts the winbar; `getmousepos().winrow` counts it too. The viewport is kept in **PDF points** (`vx`/`vy` on the "view" = one page or a spread), so zoom keeps the centre. The tex split is sized to the page aspect; pages aren't necessarily A4 (the user's `cas-dc` reports are 210×280 mm).
- **Colours:** in "theme", ink becomes the Normal fg and the paper becomes alpha (ink = 1 − min(R,G,B)). Raster figures keep their colours, using `<image>` boxes from `pdftohtml -xml -zoom 1`, run per page. The same run gives link geometry: an `<a href>` inside a `<text>` run, where `x.html#N` is an internal link to page N. Vector figures still recolour.
- **Search** uses `pdftotext -bbox` words (whole document, cached per mtime). Matches span word boundaries; a hit highlights whole words.
- **snacks conflict:** snacks.image also claims `*.pdf` (page 1 as a picture). `claim_from_snacks()` drops `pdf` from `Snacks.image.config.formats` before snacks' one-time setup and clears its `BufReadCmd *.pdf` if setup already ran. Every image buffer gets `filetype=image` from snacks, which is in cursorline's `skip_ft`. **snacks spinner bug:** a placement closed while still converting keeps its "loading" timer (the stop check ignores `closed`), which clears the `snacks.image` namespace every 80 ms. That wipes the replacement image and leaves "identify loading …" on screen. Quick re-renders (autosize + sync) hit it every time. `fix_snacks_spinner()` in `viewer.lua` wraps `Placement:close` to set `buf = -1`, one of the timer's stop conditions. Drop it once snacks fixes this upstream.
- **Sessions:** the preview's nofile window is closed on `PersistenceSavePre`, recorded in `g:Session_pdfview` and re-opened on `PersistenceSavePost` (unless exiting) and on `PersistenceLoadPost`.
- **Markdown preview (`markdown.lua`, `kind = "md"`, `<leader>pv` / `<leader>pF` in markdown buffers):** the buffer's text goes to pandoc on stdin (`-f gfm`, `--pdf-engine=typst`, `--template=github_template.typ`), run in the file's directory so relative images resolve. **Pages are shaped to the split:** the width is `cols × config.markdown.column_pt` (text keeps its size and reflows on resize) and the height follows the window's pixel aspect, so fit-page fills the window and `j`/`k` flow screen to screen. A `WinResized`/`VimResized` that changes the shape re-renders. So unlike LaTeX, the md split is **not** autosized (`autosize` is tex-only). The template styles pages like github-markdown-css (light): SF NS / SF NS Mono, h1/h2 rules, code panels, quote rule, gridded zebra tables. Keep it light-theme, because the viewer recolours. GFM, not pandoc's own Markdown, so heading ids match the `#anchors` READMEs link to. `pandoc_filter.lua` (a **pandoc** Lua filter, never `require`d) fixes what typst would drop or refuse: `<div|p align="center">` regions are wrapped in `#align(center)`; raw HTML blocks are parsed as HTML (`<table>`, `<img>`); inline tag *pairs* (`<sub>`, `<b>`, `<kbd>`, `<a href>`, …) become typst markup, and unmatched tags are dropped so brackets stay balanced; `<br>`/`<img>` are converted; Markdown table headers are bolded; and remote images are fetched with curl into `<pid>/img` (this pandoc has no HTTP; failures are remembered for the session). Missing local images and links to nonexistent anchors become text, because typst aborts the whole document on either. It renders on `TextChanged`/`TextChangedI`/`BufWritePost`, debounced by `config.markdown.delay`. The PDF is written to `*.tmp.pdf` and renamed into place, so the viewer never reads a half-written file. There's no SyncTeX here, so both directions **match text**. Forward strips the markup from the cursor line and finds the word sequence in `pdftotext` words; inverse takes the clicked word plus neighbours and finds them in the buffer's word stream. Ties go to the closest relative position. Both sides drop words that normalize to nothing (`%`, `—`) so the streams line up. Errors show as the winbar status. Per-file memory is keyed by the `.md` path (`store_key`), because the PDF lives in the per-process cache.
- **Live previews (`live.lua`):** `live.new(spec)` returns a preview module (`view`/`toggle_live`/`sync`/`inverse`/`refresh`/`compile`) with its own viewer and state; a backend only gives `kind`, `config`, `words(line)` (visible normalized words of a source line, for text-matched sync) and `command(P, src, dir, tmp)` (argv writing the PDF to `tmp`; stdin = buffer, cwd = file dir). Markdown adds page shaping + its resize autocmd; Typst is ~50 lines. Edits are **throttled, not debounced** (the first edit arms a `delay` timer, later ones ride along), so the preview keeps up while typing; compile and render each coalesce. After a recompile the sync is the only render, so `sync()` **always** renders, even when the cursor line can't be placed (`#set` lines, half-typed words, math). Otherwise the old page stays up. It also calls `V:warm()` to rasterise the visible pages while `pdftotext` runs. `V:fixed_pages()` (tex, typst) decides whether the split autosizes to the page.
- **Typst preview (`typst.lua`, `kind = "typst"`, `<leader>lv`):** `typst compile --diagnostic-format short - tmp.pdf`, debounced by `config.typst.delay`. `plain_words` drops `#set`/`#show`/`#let`/`#import` lines, comments, inline math, labels and `@refs`, and `#func(args)` heads (keeping the `[body]`).
- **Integrations:** the viewer is source-agnostic. A preview passes `integration` (a module with `live`/`toggle_live`, enabling the `z`/`f` keys), `inverse` (defaults to SyncTeX), `title` and `store_key` to `V.new`. `status` is `{ kind = "error"|"busy", text }`. Sessions handle all previews (`g:Session_pdfview = {tex=…, md=…, typst=…}`).
- It deliberately does not use image.nvim, whose global `max_height = 12` (sized for Molten) would clip a page.
