Music ~                                                    *nvim-keymaps-music*

Drives the Apple Music app (|nvim-plugins-music|); the statusline shows the
current song.

  <leader>Mo    Toggle the player (library browser + now playing)
  <leader>Mp    Play / pause (launches Music in the background if needed)
  <leader>Mn    Next track
  <leader>MN    Previous track (restarts the song when past its start)
  <leader>Ms    Search songs: the player on its Songs tab, filter open

In the player (tabs: Playlists, Artists, Albums, Songs, Queue):
  j / k, gg, G  Move                  <Tab> / <S-Tab>  Next / previous tab
  l  <Right>    Open (on a song: play) 1 .. 5           Jump to a tab
  h  <BS>       Back
  <CR>          Play: a playlist in order, an album or artist through the
                queue, a song in its context (its album, playlist, or the
                library for the Songs tab)
  a             Add to the queue (starts it when nothing is playing)
  /             Live filter: every word must match; <CR> opens the
                selection, <Esc> keeps the filter, <C-n>/<C-p> move
  o             Reveal the playing song inside its album
  <Space>       Play / pause          n / p      Next / previous track
  < / >         Seek -10s / +10s      - / +      Volume down / up (also =)
  s             Toggle shuffle        r          Cycle repeat off/all/one
  R             Reload the library    ?          Show these keys
  q / <Esc>     Close (<Esc> clears an active filter first)

In cover grids (Albums, Playlists and an artist's albums, in a kitty-graphics
terminal; elsewhere they stay lists):
  h j k l       Move between covers (also the arrow keys)
  <CR>          Open the album / playlist
  P             Play it (also works on any selection in a list)
  <BS>          Back

2. WINDOWS & BUFFERS                                   *nvim-keymaps-windows*

  <C-h>         Move to the left window
  <C-j>         Move to the lower window
  <C-k>         Move to the upper window
  <C-l>         Move to the right window
  <C-h>  (term) Exit terminal mode and move to the left window

Splitting (any buffer; see |nvim-config-layout|):
  <leader>|     Split vertically (same buffer; pick another with <leader>fb)
  <leader>-     Split horizontally
  <leader>\     Split along the window's longer side (repeat to tile)
  <leader>fb    Buffers (Telescope): <CR> here, <C-v> vsplit, <C-x> split,
                <C-t> new tab
  <leader>uw    Toggle auto panel layout
Built-in window keys worth knowing:
  <C-w>v / <C-w>s   Vertical / horizontal split
  <C-w>o            Only this window       <C-w>c   Close this window
  <C-w>=            Even out sizes         <C-w>x   Swap with the next one
  <C-w>H/J/K/L      Move the window to the far left / bottom / top / right
  <C-w>< / > / + / -  Narrower / wider / taller / shorter ([count] cells)

  <Tab>         Next buffer        (bufferline)
  <S-Tab>       Previous buffer    (bufferline)
  <leader>x     Close the current buffer (preserves window layout)
  :q            Close the current BUFFER, not Neovim      *nvim-keymaps-quit*
                (`lua/defaults/bufclose.lua`). In a split, a float, neo-tree
                or with several tabs it just closes that window/tab. In the
                last editing window it shows the next buffer (files before
                terminals, then most recent), or the dashboard when none is
                left; `:q` on that dashboard quits. Modified buffers prompt
                Save / Discard / Cancel. Terminals and unlisted buffers are
                hidden, not deleted, so their jobs keep running.
  :q!  :wq  :wq!  Same, discarding / writing first.
  :quit         The full word keeps Vim's normal behaviour (escape hatch).
  <leader>qq    Quit Neovim (`:qall`; prompts for unsaved changes)

5. EDITING OPERATORS                                   *nvim-keymaps-editing*

These come from plugins using their default mappings:

nvim-surround:
  ys{motion}{char}   Add a surrounding (e.g. `ysiw"` quotes a word)
  ds{char}           Delete a surrounding
  cs{old}{new}       Change a surrounding

Comment.nvim:
  gcc                Toggle line comment
  gbc                Toggle block comment
  gc{motion}         Comment a motion / selection
  gb{motion}         Block-comment a motion / selection

mini.ai:
  Enhanced `a`/`i` text objects (functions, args, brackets, quotes, etc.),
  scanning up to 500 lines. Use inside operators, e.g. `cif`, `va)`.

gitsigns:
  ih                 Text object selecting the current hunk (operator/visual)

  af / if            Function outer / inner   (e.g. `vif`, `daf`)

  aa / ia            Parameter (argument) outer / inner
  <leader>sp         Swap parameter with the next
  <leader>sP         Swap parameter with the previous
  ]m / [m            Next / previous function start
  ]] / [[            Next / previous class start

6. LSP, DIAGNOSTICS & FORMAT                               *nvim-keymaps-lsp*

LSP (buffer-local; bound by a global LspAttach autocmd in
`lua/defaults/lsp.lua`, so they work for every server: clangd, pyright, ruff,
ts_ls, html, cssls, emmet, texlab, tinymist, lua_ls):
  gd            Go to definition
  gD            Go to declaration
  gr            List references
  gi            Go to implementation
  gy            Go to type definition
  <leader>rn    Rename symbol
  <leader>ca    Code action            (normal / visual)
  <leader>uh    Toggle inlay hints     (enabled by default when supported)

`K` is not bound here; it has a single global owner (ufo, below).

Hover (ufo + hover.nvim):
  K             Peek the fold under the cursor; otherwise show hover docs
                via hover.nvim (LSP / Ref / man / dictionary providers)
  gK            Hover: choose a provider (LSP / Ref / man / dictionary)
  <C-n>         Hover: switch to the next provider
  <C-p>         Hover: switch to the previous provider

References (C / C++ / Python / R, see |nvim-config-refdocs|):
  <leader>K     Reference page for the word under the cursor, in a split
  <leader>fd    Search the language's reference topics (Telescope)
  K / <C-]>     Inside a page: follow the word under the cursor (<C-o> back)
  :Ref [topic]  Open a page;  :RefSearch [c|cpp|python|r]  search topics

Diagnostics:
  <leader>d     Show the diagnostic float for the current line
  [d  /  ]d     Previous / next diagnostic (with float)
  <leader>xx    Trouble: workspace diagnostics
  <leader>xb    Trouble: current-buffer diagnostics
  <leader>xs    Trouble: document symbols
  <leader>xl    Trouble: LSP references / definitions
  <leader>xq    Trouble: quickfix list
  <leader>xt    Trouble: TODO comments

Format:
  <leader>cf    Format the buffer with conform (async, LSP fallback). Files are
                also formatted on save.
  <leader>uf    Toggle format-on-save (sets g:disable_autoformat)

  C/C++ indentation follows clang-format, so `>>` and format-on-save always
  agree; see |nvim-config-project|.

Project settings & build:                                *nvim-keymaps-project*
  <leader>,     Project settings float (projectrc.nvim, |projectrc|). Inside:
                  <CR> / l      Edit (toggle, pick, type, or a JSON editor)
                  x             Reset to the inherited value
                  f             Toggle filetype scope ("[cpp]" overrides)
                  e             Open the raw .nvim/settings.json
                  T             Trust the settings file (vim.secure)
                  <Tab> 1-5     Switch tabs
                  q / <Esc>     Close
  <leader>bb    Run the project's build command in a project terminal
  <leader>br    Run the project's run command
  <leader>bt    Run the project's test command
                Then <leader>tq turns the output's errors into a quickfix list.

Spell-check (auto-enabled for tex/markdown/gitcommit/text):
  <leader>us    Toggle spell-check in the current window
  ]s  /  [s     Next / previous misspelled word
  z=            Suggest corrections
  zg  /  zG     Add the word to your spellfile / ignore it this session
  <leader>sa    Spell audit (:SpellAudit)                *nvim-spell-audit*
                Walks every issue in the buffer, top to bottom, in a float
                under the word; after each action it jumps to the next one:
                  1-9 / <CR>   replace with that suggestion
                  R            replace every occurrence of the word
                  e            type the replacement
                  s / <Space>  skip            S   ignore the word (session)
                  a            add to spellfile (zg)
                  u            undo the last action and go back to it
                  q / <Esc>    pause; <leader>sa again resumes
                It visits exactly what `]s` does, so code blocks, inline code
                and LaTeX commands (treesitter/syntax @nospell) are left out.
                Spell is switched on for the audit if it was off.

  The language is English unless a `.spelllang` file exists in the buffer's
  directory or any parent; its first line is used as 'spelllang' (e.g.
  `es,en`). Missing dictionaries are offered for download on first use.

Snippets ~

LuaSnip snippets for LaTeX live in `lua/snippets/tex.lua`. Math-mode ones
fire only inside a math zone, detected via `vimtex#syntax#in_mathzone()`:

  mk / dm       Inline $...$ / display \[...\] math (text mode)
  //            \frac{}{}; "x/" expands to \frac{x}{}
  @a .. @w      Lowercase Greek (\alpha .. \omega)
  @G .. @W      Uppercase Greek (\Gamma .. \Omega)
  xhat, xbar    Postfix decorations -> \hat{x}, \bar{x}
  x2            Auto-subscript -> x_{2}
  template      Full document skeleton
  beg, fig, tab, eqn, ali, pmat   Common environments

Because the math-zone check is a VimTeX function, these snippets go silent if
VimTeX fails to initialise. See |nvim-plugins-vimtex|.

Typst snippets live in `lua/snippets/typst.lua` and reuse the LaTeX
triggers where they still make sense. Math is detected with treesitter
(inside `$...$`, not in a "string" there). The set is lighter: Typst
already turns `->`, `=>`, `<=`, `>=`, `!=`, `...`, `oo`, `RR` and `x/y` into
symbols, and no autosnippet may be a prefix of a native name (`delta`,
`sqrt`, `liminf`, `parallel`, ...), so limits/sums are <Tab> snippets.

  mk / dm       Inline $...$ / display $ ... $ math (text mode)
  //            frac(_, _) (x/y is already a fraction)
  x2, __, td    x_2, _(...), ^(...); sr ^2, cb ^3, invs ^(-1)
  @a .. @W      Greek, Typst names (alpha .. Omega)

16. WRITING COMPANION (CLAUDE)                         *nvim-keymaps-writing*

A cheap Claude model (Haiku, through the `claude` CLI and your Claude Code
login) as copy editor, developmental editor and reader. Nothing runs on its
own: text leaves Neovim only when you press one of these. See
|nvim-config-writing|.

  <leader>Wg    Grammar audit: check, then walk every issue in the float of
                |nvim-spell-audit| (1-3 fix, e edit, s skip, d dismiss for
                good, u undo, q pause; <leader>Wg again resumes)
  <leader>WG    The same, plus style and clarity hints
  <leader>Wp    Grammar audit of the paragraph under the cursor only
  <leader>Wo    Reverse outline in a right panel: per paragraph a summary,
                its role and flags (unsupported claim, gap, contradiction,
                undefined term...), plus document-level notes. In the panel:
                <CR> jump, ]f / [f next / previous flag, r re-run, q close
  <leader>Wa    Rigor review (research writing): Claude reads the whole
                document as a peer reviewer and reports loose reasoning, not
                grammar: unsupported claims, overclaiming (causal language
                from correlations, "proves", "always"), non-sequiturs, named
                fallacies, inconsistencies across sections (numbers,
                definitions), misused statistics, method gaps, undefined
                terms, vague claims, and facts to verify. A report panel shows
                the verdict, strengths, priorities and findings (<CR> jump,
                w walk, r re-run, q close); the findings are then walked:
                1 apply the suggested rewording (when wording alone fixes it),
                e edit, m insert a TODO(review) comment under the passage (in
                the file's comment syntax), s skip, d dismiss, u undo, q pause
  <leader>Wr    Rewrite the paragraph (normal) or selection (visual) with an
                instruction (concise, formal, simpler, active voice, flow,
                translate, custom). Preview float: <CR>/a accept (one undo
                step), r retry, q cancel
  <leader>Wq    Ask about the paragraph / selection (answered with the whole
                document as context)
  <leader>Wc    Companion chat in a split (a Claude chat buffer primed to read
                the file)
  <leader>Wd    Toggle the AI diagnostics (grammar issues and outline flags)
  <leader>Wx    Clear the AI issues of this buffer
  :Writing {grammar|style|outline|rigor|rewrite|ask|chat|clear}

Grammar issues and rigor findings are also diagnostics (sources "claude" and
"rigor"), so ]d / [d, Trouble and the sign column show them.
