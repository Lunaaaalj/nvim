CONTENTS                                                       *nvim-plugins*

Plugins are managed by `lazy.nvim`; each lives in its own file under
`lua/plugins/`. Keymaps below are summarized — see |nvim-keymaps| for the
authoritative, grouped reference.

  1. LSP & completion .......................... |nvim-plugins-lsp|
  2. Editing ................................... |nvim-plugins-editing|
  3. Navigation & files ........................ |nvim-plugins-navigation|
  4. UI ........................................ |nvim-plugins-ui|
  5. Git ....................................... |nvim-plugins-git|
  6. Test & debug .............................. |nvim-plugins-testdebug|
  7. Notebooks & markdown ...................... |nvim-plugins-notebooks|

1. LSP & COMPLETION                                        *nvim-plugins-lsp*

nvim-lspconfig ~  (neovim/nvim-lspconfig)
  LSP client configuration framework. `lua/defaults/lsp.lua` sets up
  `tsserver` with cmp capabilities and the on_attach maps gd / K / gr /
  <leader>rn (K is then overridden by hover.nvim).

mason.nvim + mason-lspconfig.nvim ~  (mason-org/*)
  Installs and manages LSP servers (clangd, pyright, ruff, ts_ls, html,
  cssls, emmet, texlab, lua_ls, r_language_server). cmp capabilities are set
  for all servers via `vim.lsp.config("*")`, per-server overrides via
  `vim.lsp.config(name)`, and mason-lspconfig's `automatic_enable` starts each
  installed server. Build hook: `:MasonUpdate`.

nvim-cmp ~  (hrsh7th/nvim-cmp)
  Completion engine, loaded on InsertEnter. Sources: nvim_lsp, luasnip
  (priority group), then buffer and path. Maps: <C-Space> complete, <C-e>
  abort, <CR> confirm, <Tab>/<S-Tab> next/prev or snippet jump.

LuaSnip ~  (L3MON4D3/LuaSnip, + friendly-snippets)
  Snippet engine driving cmp expansion. Loads VSCode-format snippets and
  custom Lua snippets; autosnippets enabled.

conform.nvim ~  (stevearc/conform.nvim)
  Formatter runner. Formats on save (2s timeout, LSP fallback) and on
  <leader>cf. Formatters: python = isort+black, lua = stylua, c/cpp =
  clang_format.

trouble.nvim ~  (folke/trouble.nvim)
  Pretty list for diagnostics, symbols, references and quickfix. Diagnostics
  view auto-closes when empty. Maps: <leader>xx/xb/xs/xl/xq (and <leader>xt
  for TODOs via todo-comments).

2. EDITING                                             *nvim-plugins-editing*

nvim-treesitter ~  (nvim-treesitter/nvim-treesitter)
  Syntax parsing/highlighting. Loaded eagerly; build hook `:TSUpdate`. Ensured
  parsers: lua, vim, vimdoc, bash, python, cpp, c, markdown, markdown_inline.
  Legacy regex highlighting disabled. Parsers install to stdpath("data")/parsers.

nvim-treesitter-context ~  (nvim-treesitter/nvim-treesitter-context)
  Sticky header showing the enclosing scope (max 3 lines, cursor mode).
  Toggle with <leader>ut.

mini.ai ~  (echasnovski/mini.ai)
  Extended a/i text objects (n_lines = 500). Used inside operators/visual.

nvim-surround ~  (kylechui/nvim-surround)
  Add/change/delete surroundings with ys / cs / ds (default mappings).

Comment.nvim ~  (numToStr/Comment.nvim)
  Toggle comments with gcc / gbc / gc{motion} / gb{motion}.

nvim-autopairs ~  (windwp/nvim-autopairs)
  Auto-closes brackets, quotes and parens.

treesj ~  (Wansmer/treesj)
  Toggle split/join of code blocks (max_join_length = 150). Map: <leader>j.

nvim-ufo ~  (kevinhwang91/nvim-ufo)
  Treesitter+indent folding. foldcolumn = 1, folds start open (foldlevel 99).
  Maps: zR open all, zM close all, zr open-except-kinds, K peek-fold-then-hover.

flash.nvim ~  (folke/flash.nvim)
  Labeled jump motions. `s` jump, `S` treesitter select, `r` remote,
  <C-s> toggle in search. Default `/` search is left unmodified.

grug-far.nvim ~  (MagicDuck/grug-far.nvim)
  Project-wide search & replace with live preview. <leader>sr (prefills a
  `*.<ext>` filter), <leader>sR on a visual selection.

todo-comments.nvim ~  (folke/todo-comments.nvim)
  Highlights FIX/TODO/HACK/NOTE comments. <leader>ft Telescope, <leader>xt
  Trouble, ]t / [t to jump.

3. NAVIGATION & FILES                               *nvim-plugins-navigation*

telescope.nvim ~  (nvim-telescope/telescope.nvim, + fzf-native)
  Fuzzy finder for files, keymaps, colorschemes, TODOs, etc. fzf-native needs
  `make`. Used by <leader>ff, <leader>?, <leader>cs, <leader>ft.

neo-tree.nvim ~  (nvim-neo-tree/neo-tree.nvim)
  Sidebar file explorer (width 34), the default explorer. Toggle: <leader>n.
  The winbar has four icon-only source tabs, spread evenly with no
  separators: Files, Buffers, Git, Claude. The active one is underlined in
  the scheme's accent. The name of the active source is shown in the
  bufferline offset above the tree. Tabs are defined once in
  `lua/neotree_tabs.lua` (BMP Nerd Font glyphs written as \u{} escapes).
  Depends on nvim-window-picker (s1n7ax/nvim-window-picker) so `w` in the tree
  opens the file in a window you choose by letter.

oil.nvim ~  (stevearc/oil.nvim)
  Edit the filesystem as a buffer; shown in a float, hidden files visible.
  Not the default explorer. Open parent dir with `-`.

harpoon ~  (ThePrimeagen/harpoon, branch harpoon2)
  Pin a handful of files for instant jumps. <leader>Ha add, <leader>Hh menu,
  <leader>1-4 jump.

bufferline.nvim ~  (akinsho/bufferline.nvim)
  Buffer tab bar with diagnostics, thin separators, and a neo-tree offset
  labelled with the active neo-tree source (icon + name). Navigate
  with <Tab>/<S-Tab>, close with <leader>x.

toggleterm.nvim ~  (akinsho/toggleterm.nvim)
  Multiple toggleable terminals, VSCode-style. <leader>t toggles shell #1 in a
  vertical side panel; numbered shells open with a count prefix on <C-\> (e.g.
  2<C-\> -> shell #2), and :TermSelect (<leader>ts) lists/switches between them.
  <leader>tn opens a fresh shell, <leader>tf/th give float/horizontal terminals,
  and <leader>tp / <leader>tN toggle pinned Python / Node REPLs. Each terminal
  window carries a winbar tab-strip of every open shell with the current one
  bracketed. Terminals stay transparent (shade_terminals off). See also the
  terminal-mode window-nav maps in :help nvim-keymaps.

which-key.nvim ~  (folke/which-key.nvim)
  Popup of pending keybindings after a 500ms delay, with named groups for the
  leader prefixes (AI, Code, Debug, Find, Git, Harpoon, Molten, Output,
  Session, Run/Rename, Search, Test, UI, Trouble).

4. UI                                                       *nvim-plugins-ui*

lualine.nvim ~  (nvim-lualine/lualine.nvim)
  Statusline (auto theme). Sections: mode | branch+diff | filename | LSP
  diagnostics+filetype | progress+location. ~60fps refresh, tabline always on.

noice.nvim ~  (folke/noice.nvim)
  Replaces the cmdline, messages and popupmenu UI. Popup cmdline, LSP
  progress/hover/signature, presets: bottom_search, command_palette,
  long_message_to_split, lsp_doc_border.

nvim-notify ~  (rcarriga/nvim-notify)
  Notification backend for Noice (configured only inside the Noice spec):
  `slide` stage (moves, never fades: fading left dark corners on the
  transparent toasts; `static` is the fallback), 3s timeout. Noice routes
  `vim.notify` through it.

snacks.nvim dashboard ~  (folke/snacks.nvim)
  Minimal single-column start screen, everything centered: the header art
  (`dashboard-header.txt` in the config root, verbatim; a built-in Python
  snake otherwise), a live clock + date, a GitHub stats line (open PRs ·
  open issues · contributions in the last year · current streak), and a
  one-line key hint (f find · r recent · s session · c config · q quit).
  The width follows the art's widest line. g/n/p/l/m (grep, new file,
  projects, Lazy, Mason) are bound too, just not listed. The clock ticks
  once a minute and only while the dashboard is visible.
  The stats come from one async `gh api graphql` call, cached 30 min in
  `stdpath("cache")/dashboard/stats.json`, so the counts are exact (not
  capped at 30). Without `gh`/auth the stats line is hidden. "issues" means
  assigned to you; pass `issues = "author"` to `dashboard_data.setup()` in
  `lua/plugins/snacks.lua` to count issues you filed instead. Colors are
  muted text plus one accent taken from the active scheme.
  The `scroll` module (smooth scrolling) is enabled from the same spec:
  140ms outQuad per jump (<C-d>, n, G, ...), 50ms linear for held-key repeats.

barbecue.nvim ~  (utilyre/barbecue.nvim)
  Winbar breadcrumbs of the code location, powered by nvim-navic.

nvim-navic ~  (SmiteshP/nvim-navic)
  LSP-driven location provider feeding barbecue's breadcrumbs.

smear-cursor.nvim ~  (sphamba/smear-cursor.nvim)
  Animated cursor trail; owns all cursor animation. Stiffer than the defaults
  (settles faster). Its trail fades into `colors.terminal_bg` (#181818,
  Alacritty's default bg) because a transparent Normal has no bg to fade into.

tiny-glimmer.nvim ~  (rachartier/tiny-glimmer.nvim)
  Flash on yank: the yanked text highlights (Visual) and fades out over
  ~300ms toward `colors.terminal_bg`. Paste/search/undo flashes are off so
  p/P, n/N and u keep their normal mappings.

mini.indentscope ~  (echasnovski/mini.indentscope)
  Indent-scope guide (│) that grows out from the cursor (80ms). Disabled in neo-tree, toggleterm,
  lazy, mason, help, noice and trouble buffers.

typr ~  (nvzone/typr)
  Typing practice (`:Typr`, <leader>ty) and a WPM/accuracy stats dashboard
  (`:TyprStats`, <leader>tY). UI rendered by nvzone/volt. Lazy-loaded.

gitsigns.nvim ~  (lewis6991/gitsigns.nvim)

diffview.nvim ~  (sindrets/diffview.nvim)

git-conflict.nvim ~  (akinsho/git-conflict.nvim)

neotest ~  (nvim-neotest/neotest, + neotest-python)

7. NOTEBOOKS & MARKDOWN                               *nvim-plugins-notebooks*

molten-nvim ~  (benlubas/molten-nvim, pinned <2.0.0)
  Runs code in Jupyter kernels. Build hook `:UpdateRemotePlugins`. Detects the
  terminal at startup: image-capable terminals (Kitty/WezTerm/Ghostty) use
  image.nvim for inline plots; otherwise `molten_image_provider = "none"` and
  output is virtual text. Output window max height 20, wrap on, auto-open off.
  See |nvim-notebooks| for the full workflow.

image.nvim ~  (3rd/image.nvim)
  Kitty-graphics image backend; loaded ONLY when the terminal supports it.

jupytext.nvim ~  (GCBallesteros/jupytext.nvim)
  Converts `.ipynb` <-> markdown on the fly (style = markdown, ft = markdown)
  so notebooks edit as plain markdown. Calls a bare `jupytext` resolved from
  the Neovim host venv on `$PATH`.

quarto-nvim ~  (quarto-dev/quarto-nvim)
  `.qmd` support: ft=quarto lazy-load, per-language LSP inside chunks via
  otter.nvim (lspFeatures.chunks = "curly", matching ```{r}/```{python}
  headers). codeRunner disabled — cell execution stays on Molten. Also
  provides :QuartoPreview / :QuartoClosePreview (<leader>op / <leader>oP).
  See |nvim-notebooks-quarto| for the full workflow.

otter.nvim ~  (jmbuhr/otter.nvim)
  Per-chunk LSP backend used by quarto-nvim; activated automatically when
  quarto-nvim's lspFeatures are enabled, no separate setup() call.

render-markdown.nvim ~  (MeanderingProgrammer/render-markdown.nvim)
  In-buffer rendering of markdown (headings, code blocks, tables, etc.).

8. PROSE & LATEX                                         *nvim-plugins-prose*

zen-mode.nvim ~  (folke/zen-mode.nvim)
  Distraction-free centered editing (90-col window). Toggle with <leader>z.
  Inside zen it hides line numbers, the sign/fold columns, cursorline, git
  signs and the statusline, and keeps the transparent background (no backdrop
  dim). Pairs with twilight.nvim to dim everything except the section under the
  cursor, and pauses the ambience plugins (illuminate, mini.indentscope,
  satellite, precognition) for the duration, restoring them on exit.

vimtex ~  (lervag/vimtex)                              *nvim-plugins-vimtex*
  LaTeX editing and compilation. Loaded eagerly (`lazy = false`) -- VimTeX
  must register its ftplugin before the first `.tex` buffer opens.

  Pinned to tag v2.18. VimTeX's HEAD raised its floor to Neovim 0.12.4 on
  2026-07-22; on an older Neovim the version gate `finish`es ftplugin/tex.vim
  *before* `vimtex#init()`, which silently removes every mapping, the latexmk
  compiler, and `vimtex#syntax#in_mathzone()` -- and losing that last one
  disables all math autosnippets in `lua/snippets/tex.lua`. v2.18 is the last
  tag accepting Neovim 0.10+. Drop the pin after upgrading to 0.12.4.

  Viewer: Skim, with forward search, window activation and the reading bar
  enabled; `vimtex_view_forward_search_on_start` is off, so `<leader>lv` is
  the explicit way to open the PDF. Skim is driven over AppleScript/JXA
  rather than CLI flags, so macOS may ask for automation permission the first
  time Neovim controls it (Settings -> Privacy & Security -> Automation);
  denying it makes `<leader>lv` fail silently.

  Note that VimTeX starts viewers detached, so *any* viewer failure is
  invisible from inside Neovim. When `<leader>lv` appears to do nothing, run
  `<leader>li` (:VimtexInfo) and try the printed viewer command in a shell,
  where stderr is actually visible.

  Treesitter highlighting is disabled for `latex` in
  `lua/plugins/treesitter.lua` so VimTeX owns syntax and conceal; the parser
  stays installed for folding, text objects and context.

  Maps: see |nvim-keymaps-latex| for the `<leader>l...` group, text objects
  and snippets. VimTeX's own `\l...` maps remain available too.

9. COLORSCHEMES                                   *nvim-plugins-colorschemes*

All are lazy-loaded at priority 1000 and render transparently (native option
where available, otherwise the global transparency autocmd — see
|nvim-config-colorscheme|). Pick and persist one with <leader>cs. Each native
option below reads `g:ui_transparent`, so <leader>ub switches all of them to
their solid backgrounds (|nvim-config-ui-toggle|).

  catppuccin        (catppuccin/nvim)            transparent_background
  kanagawa          (rebelot/kanagawa.nvim)      transparent
  kanso             (webhooked/kanso.nvim)       transparent  (default fallback)
  lackluster        (slugbyte/lackluster.nvim)   transparent normal bg
  nightfox          (EdenEast/nightfox.nvim)     transparent
  everforest        (neanias/everforest-nvim)    full transparency
  melange           (savq/melange-nvim)          via global autocmd only
  gruvbox-material  (sainnhe/gruvbox-material)   full transparency
  zenbones          (zenbones-theme/zenbones.nvim)  transparent; variants
                    forestbones / neobones / kanagawabones / seoulbones

Warm set (all but vesper follow 'background', so <leader>uB switches them):
  rose-pine         (rose-pine/neovim)           styles.transparency; main /
                    moon / dawn (light)
  kanagawa-paper    (thesimonho/kanagawa-paper.nvim)  transparent; ink /
                    canvas (light)
  bamboo            (ribru17/bamboo.nvim)        transparent; vulgaris /
                    multiplex / light
  flexoki           (kepano/flexoki-neovim)      via global autocmd only;
                    flexoki-dark / flexoki-light
  evergarden        (comfysage/evergarden)       transparent_background; the
                    spec picks fall (dark) / summer (light) from 'background'
  vesper            (datsfilipe/vesper.nvim)     transparent; dark only

10. AI                                                      *nvim-plugins-ai*

claudecode.nvim ~  (coder/claudecode.nvim, + snacks.nvim)
  Claude Code integration. Terminal: right split, 32% width, snacks provider,
  auto-close. Diffs reviewed in a vertical split, auto-close on accept. Maps:
  <leader>ac/af/ar/aC/am/ab/as/aa/ad — see |nvim-keymaps-claude|.

claude_chats ~  (local: lua/claude_chats/)
  Runs `claude` in regular terminal buffers (many at once) with the same IDE
  env claudecode.nvim uses, so selections/diffs still work. Past sessions are
  read from ~/.claude/projects/<cwd>/*.jsonl (titles: /rename > AI title >
  last prompt). Adds a Claude neo-tree source tab next to Files/Buffers/Git.
  Maps: <leader>an/aR/al — see |nvim-keymaps-claude|.
