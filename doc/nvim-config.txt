1. INTRODUCTION                                          *nvim-config-intro*

An opinionated Neovim configuration written in Lua, using `lazy.nvim` as the
plugin manager. It targets macOS and is primarily run in Alacritty.

Design goals:
  - A clean, minimal UI with universal background transparency so the
    terminal background always shows through.
  - An earthy, low-contrast palette (grays / greens / browns) with a set of
    interchangeable dark and light colorschemes, persisted across sessions.
  - A small, productive plugin set covering LSP, completion, fuzzy finding,
    git, testing, debugging, and Jupyter-style notebook evaluation.

Leader is <Space>; localleader is "\". For the full keymap reference see
|nvim-keymaps|. Two in-editor discovery aids:
  - `<leader>?`   Telescope live-searchable list of ALL keymaps
  - `<leader>k`   Hand-curated cheatsheet in a floating window

2. REQUIREMENTS                                   *nvim-config-requirements*

Core:
  - Neovim (recent version with Lua support)
  - git                  Plugin management and version control features
  - macOS                Recommended / tested platform
  - Alacritty            Terminal the transparency is tuned for (any terminal
                         works; light schemes need a light terminal background)

External binaries:
  - make                 Builds `telescope-fzf-native`
  - lazygit              Required by `lazygit.nvim`
  - sioyek               PDF viewer used by `vimtex` (view method)
  - clang-format, black, isort, stylua    Formatters used by `conform.nvim`
  - cppman, groff        C++ references (`pipx install cppman`,
                         `brew install groff`); see |nvim-config-refdocs|

Notebooks / Molten (optional, only if you use notebooks):
  - A Python venv at `~/.virtualenvs/neovim` providing the Neovim Python host.
    It must contain `pynvim`, `jupyter_client`, and `jupytext`. Homebrew's
    python3 is PEP-668 externally-managed, so deps are NOT installed there.
  - `~/.local/bin/jkernel`   Helper to register per-project venvs as Jupyter
                             kernels (not part of this repo). See |nvim-notebooks|.
  - A Kitty-graphics terminal (Kitty / WezTerm / Ghostty) is needed ONLY for
    inline notebook images; Alacritty works for everything else via virtual
    text. See |nvim-notebooks|.

LSP servers `clangd` and `pyright` are installed automatically by mason; you
do not need to install them yourself.

==============================================================================
3. INSTALL                                             *nvim-config-install*

1. Clone into your Neovim config path: >
     git clone <repo-url> ~/.config/nvim
<
2. Start Neovim. `lazy.nvim` bootstraps itself and syncs all plugins on first
   launch. If anything looks off, run `:Lazy sync`.

3. For notebooks, after molten-nvim installs, run `:UpdateRemotePlugins` and
   restart Neovim (see |nvim-notebooks|).

Help tags: this documentation lives under `doc/`. If `:help nvim-config` does
not resolve, build the tag index once with: >
     :helptags ~/.config/nvim/doc
<

4. ARCHITECTURE                                   *nvim-config-architecture*

Load order:
  `init.lua`
    -> `lua/defaults/init.lua`
         -> `lua/defaults/options.lua`   editor options
         -> `lua/defaults/keymaps.lua`   core (non-plugin) keymaps
         -> `lua/defaults/lazy.lua`      lazy.nvim bootstrap + plugin import
    -> colorscheme restore + transparency autocmd + Python host setup
    -> all plugin specs under `lua/plugins/`

Directory layout:
  - `lua/defaults/`   Core Neovim settings, not plugin-specific: options,
                      keymaps, lazy bootstrap, and LSP on-attach (`lsp.lua`).
  - `lua/plugins/`    One file per plugin (or tightly related group); each
                      returns a lazy.nvim spec table. lazy.nvim auto-imports
                      everything in this directory.
  - `lazy-lock.json`  Locked plugin versions.

To add a plugin, create a new file under `lua/plugins/` returning a spec: >
     return {
       "author/plugin-name",
       opts = { ... },
     }
<

5. EDITOR OPTIONS                                      *nvim-config-options*

Set in `lua/defaults/options.lua`:
  - `number` + `relativenumber`   Hybrid line numbers.
  - `tabstop`/`softtabstop`/`shiftwidth` = 4, `expandtab`   4-space indents.
                                  C-family buffers take theirs from
                                  clang-format instead (|nvim-config-project|).
  - `autoindent` + `smartindent`  Automatic indentation.
  - `wrap` + `linebreak`          Soft-wrap long lines at word boundaries.
  - `netrw_banner = 0`            Hide the netrw banner.
  - `cursorline`                  Only in the focused regular-file window;
                                  off in inactive splits, terminals, floats
                                  (incl. Zen), the dashboard, lazy and mason.
                                  neo-tree keeps its own selection line. Set
                                  `w:no_cursorline` to opt a window out.
                                  Styling lives in `lua/defaults/cursorline.lua`;
                                  see |nvim-config-cursorline|.
  - `fillchars`                   Clean window chrome: blank `eob` (no `~` on
                                  empty lines), thin `│` window separator, `─`
                                  horizontal split, and fold arrows.
  - `pumblend`/`winblend` = 10    Slight transparency on the completion popup
                                  and floating windows so they sit lightly
                                  over the editor instead of as solid blocks.

Diagnostics (`vim.diagnostic.config`) use icon signs instead of Neovim's
default `E`/`W`/`I`/`H` letters, are sorted by severity, and show virtual
text. lua_ls is told `vim` and `Snacks` are globals via `.luarc.json` in the
config root, so editing the config itself produces no spurious
"undefined global" warnings.

An autocmd runs `:checktime` on FocusGained / BufEnter / CursorHold so files
changed on disk are auto-reloaded.

Python host (`lua/defaults/init.lua`): `g:python3_host_prog` points at
`~/.virtualenvs/neovim/bin/python`, and that venv's `bin` is prepended to
`$PATH` so a bare `jupytext` resolves. See |nvim-notebooks|.

6. COLORSCHEMES & TRANSPARENCY                     *nvim-config-colorscheme*

Persistence ~
The last-used colorscheme is written to `stdpath("state")/colorscheme`
(machine-local, outside the config repo, so theme changes never show up in
`git status`) and restored on startup. Any `:colorscheme` call triggers an
autocmd that saves the name, so your choice survives restarts. If the saved
scheme can't be loaded (removed plugin, typo, fresh machine), startup falls
back to `kanso` instead of erroring. A legacy `.colorscheme` in the config
root is migrated once, then ignored (it is in `.gitignore`).

Picker ~
  - `<leader>cs`   Opens Telescope with live colorscheme preview; the
                   selection is persisted automatically.

Universal transparency ~
By default every scheme renders with no editor background so the terminal
background shows through. This is enforced two ways, both driven by
`g:ui_transparent`:
  1. Native `transparent` options set per-plugin where supported (each theme
     spec passes `vim.g.ui_transparent` instead of a literal `true`).
  2. A global `ColorScheme` autocmd in `lua/defaults/init.lua` strips the
     background of core highlight groups (`transparent_groups`) after ANY
     scheme loads — covering schemes without a transparency option (e.g.
     melange). Add new groups to that list if a plugin leaves a background.
     It does nothing in solid mode.

Current line ~                                       *nvim-config-cursorline*
In transparent mode the style comes from `g:cursorline_style`, cycled with
`<leader>uc` (not persisted):
  `number`     Accent, bold line number only, no line decoration (default).
               The accent is the scheme's `Function` fg.
  `underline`  One faint rule in a single colour (explicit `sp` = `LineNr`
               fg, so it doesn't change colour under every token).
  `band`       A soft tint (Normal fg blended ~7% into black/white). Over a
               translucent Alacritty this needs
               `colors.transparent_background_colors = true` in
               `alacritty.toml`, otherwise it is drawn as an opaque stripe.
In solid mode (|nvim-config-ui-toggle|) the scheme's own `CursorLine` band and
`CursorLineNr` are kept as is.

Toggles ~                                             *nvim-config-ui-toggle*
  `<leader>ub`  `:ToggleTransparency`  transparent <-> solid background
  `<leader>uB`  `:ToggleBackground`    'background' dark <-> light
Both live in `lua/defaults/ui_toggle.lua` and persist to
`stdpath("state")/ui.json`, restored before lazy.nvim loads the themes. A
toggle re-runs the active theme's lazy `init`/`config` (nightfox and
catppuccin recompile automatically when their options change) and reloads it.

Light colorschemes only look right over a light background, so switching to
light while transparent forces solid mode, and switching back to dark restores
transparency. A scheme with no variant for the target is left as is, with a
warning: either it pins 'background' back (nightfox; use dayfox) or it just
keeps drawing dark (vesper). The toggle checks the colors the scheme actually
drew, not just 'background'. In Alacritty, solid mode also
sets `window.opacity=1` live via `alacritty msg config`; transparent mode and
quitting Neovim reset it to the value in `alacritty.toml`.

Installed schemes (one file each under `lua/plugins/`): catppuccin, kanagawa,
kanso, lackluster, nightfox, everforest, melange, gruvbox-material, zenbones
with its variants (forestbones, neobones, kanagawabones, seoulbones), and a
warm set: rose-pine, kanagawa-paper, bamboo, flexoki, evergarden, vesper. See
|nvim-plugins-colorschemes|.

7. PROJECT SETTINGS                                    *nvim-config-project*
                                                    *nvim-config-clang-indent*
Per-project settings in the spirit of VS Code's `.vscode/settings.json`, by
projectrc.nvim (|nvim-plugins-projectrc|, its own docs: |projectrc|): a float
(`<leader>,` or `:ProjectRC`, keys in |nvim-keymaps-project|) edits
`.nvim/settings.json` and, for clang-format/clangd settings, those tools' own
`.clang-format` / `.clangd`, so shells, CI and other editors agree.

It also makes C, C++, Objective-C, CUDA and proto indentation follow
clang-format: 'shiftwidth', 'tabstop' and 'expandtab' come from
`clang-format --dump-config` for the file, and without a `.clang-format`
both the editor and conform's clang_format use LLVM style with
`IndentWidth: 4`. So `>>` and format-on-save always agree.

Settings that run something (build commands, environment, launch configs,
clangd's query driver, the pyright venv) stay off until the settings file is
trusted (`T` in the float), using the same hash-based trust as 'exrc'.

8. LANGUAGE REFERENCES                                 *nvim-config-refdocs*

`lua/refdocs/` shows reference pages for C, C++, Python and R, offline and
from the tools that already know your installed versions:

  C         man pages, library sections first (3, 2, then 1): `printf` is
            printf(3), not the shell command
  C++       cppreference.com through `cppman`; `v.push_back` is resolved to
            std::vector::push_back using clangd's type of `v`
  Python    `python -m pydoc`, run with the file's project venv (`.venv`,
            `venv`, `env` upward, then $VIRTUAL_ENV), so `np.linspace` is the
            numpy that project has; `import x as y` aliases are resolved
  R         the installed help pages (Rd2txt), any installed package,
            `pkg::fn` honoured; runs in the file's dir so renv applies

The language is the buffer's filetype, or in Quarto / R Markdown / Markdown
the language of the code chunk under the cursor.

  K             hover.nvim: the "Ref" provider comes right after LSP; switch
                to it with <C-n> (or `gK` to choose)
  <leader>K     Full page in a reusable split (:Ref [topic])
  <leader>fd    Telescope over every topic of the language, page as preview;
                <C-e> looks up the typed text verbatim (:RefSearch [lang])

Inside a page, `K` / <C-]> follow the word under the cursor relative to the
page (`push_back` in std::vector's page, `move_to_end` in OrderedDict's) and
<C-o> goes back; `gO` lists the sections; `q` closes.

C++ pages are fetched from cppreference the first time and cached in
~/.cache/cppman; run `cppman -c` once to cache everything for offline use.

9. WINDOW LAYOUT                                        *nvim-config-layout*

Panels (terminals, including Claude's; reference pages; `:vert help`) live in
one column on the right, so the editor keeps its width however many are open
(`lua/layout/`):

  * the first panel opens as the right column, narrowed if needed so the
    editor keeps 88 columns (a panel is never narrower than 40);
  * every next one is stacked below it in that column, and the column's
    heights are evened out;
  * the column keeps its width, including one you set by hand (<C-w>< / >).

Only panels that open as the rightmost column are moved: a bottom terminal
(<leader>th) or a split you make inside the column stays where it is.
<leader>uw turns this off.

'equalalways' is off: a split halves only the window you split and nothing
else is resized. Sidebars (neo-tree) and panels have fixed widths; file
windows never do, so they absorb size changes.

Split any buffer yourself with <leader>| (vertical), <leader>- (horizontal)
or <leader>\ (along the window's longer side; repeating it tiles: vertical,
then horizontal, then vertical...). |nvim-keymaps-windows| lists the keys.
